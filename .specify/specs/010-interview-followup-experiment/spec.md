# Feature Spec 010（微型实验）：人生设计随访——访谈记忆最小闭环

- **Branch**: deploy-rebased｜**Created**: 2026-09-19（规格席位；用户拍板"开始"）
- **性质**: **实验，不是功能**。目的=用一周回答一个生死问题：当访谈能记住上次内容时，用户（产品主人本人，第一个用户）会不会自发回来做第三次。
- **背景**: 产品存在性讨论（09-19）后方向收敛——"访谈驱动的伴随"是唯一活方向；本实验是它的最小验证，**在 009 收尾之上、冻结窗（9/23-10/2）之前的窗前允许项（9/19-9/22）**。

## 1. 假设与判据（可证伪）

- **假设**: 访谈记忆 → 回访动机。
- **成功判据（全部满足才算方向成立）**:
  1. T2 技术验收：第二次访谈中 AI **主动引用 ≥1 条**上次存入的记忆事实，且内容准确非编造；
  2. 观察窗（T2 后 30 天）内，用户**未经提醒自发**完成第三次访谈。
- **失败处置**: 判据 2 不成立 → 方向证伪，产品按 009 完成收尾后停建，写 AAR 复盘文档。

## 2. 执行契约（刻意最小，防"顺手做全"）

### T0（用户本人操作，零代码，今天可做）
- 在生产站跑一次完整人生设计访谈（现有失忆版即可）。
- 结束后从访谈产出中挑 **2-3 条原则**（格式：原则正文/触发场景/下回动作），`POST /api/user-memory` 入库：
  - `fact_type` 暂用 `behavior` 或 `goal`（**不做** `principle` 新类型——那是 006 的事，本实验零迁移）；
  - `fact_key` 用 `interview_principle_1..n`，`fact_value` 存"原则：…；场景：…；下回：…"。
- 入库后 `GET /api/user-memory` 核对可见。

### T1（执行会话，≤1 小时，≤2 文件，零迁移）
- `life_design_service` 的 LLM 调用前注入 `user_context_service` 产出的 `memory_facts`（**复用现有 build/serialize 链**，003 已在产）；
- prompt 纪律：记忆作为"此用户已知背景"注入，并加一句硬规则——"若记忆中存在该用户此前访谈沉淀的原则，开场或首个提问须自然引用其中一条，不得复述全文，不得编造记忆中没有的内容"；
- **禁止扩散**：不做原则提炼 UI、不做 principle 类型、不做访谈历史页、不改前端。任何"顺手"扩展=违约。

### T2（T1 上产后，用户本人操作）
- 跑第二次访谈，验收判据 1；记录 AI 原话为证据。

### T2b（同日，对照组——必做，测"提示词缺口"）
- 同一份背景材料，在 ChatGPT/豆包（开持久记忆）里跑同款第二次访谈。
- **判读**：若通用模型记忆版体验与本产品打平 → "AI 记得你"无缺口，方向降级为作品收尾；只有本产品做出 ChatGPT 做不到的事（记忆联动时间线/条件账本/考研情报橱窗的结构化判断）才算立住。缺口=结构化台账×具体决策流程，不是"记得你"三个字。

## 3. 验收

1. T1 交付：改动 diff ≤2 文件；现有 1896 基线测试全绿；生产冒烟=带登录态调一次人生设计端点，日志/响应中可见记忆注入。
2. 负例：无记忆事实的新用户跑访谈——行为与现状完全一致（不引用、不报错）。
3. 判据 2 的观察窗记录方式：用户自行记日期，30 天后回看。

## 4. 非目标

- 006 原则库全量实施（principle 类型/提炼/空话检测）——实验证伪了也白做，证真了再按 006 正式立项
- 任何前端改动、任何新表、任何新端点
- 冻结窗（9/23-10/2）内的任何后续工作

# Feature Spec 007：行为设计微机制（福格二维度 · 轻量）

- **Branch**: deploy-rebased｜**Created**: 2026-09-14（规格席位，用户拍板选 B 轻量立案）
- **依据**: `docs/决策分析-行为设计书籍蒸馏与护城河-2026-09-14.md`（A/B/C/D 拍板=B）+ `$ai-project-fupan` 集成先例 + 008 行为设计实验纪律
- **范围纪律**：**不拆书**（不做整本蒸馏）、**不新增页面**、**不新增后端端点**（纯前端机制；文案生成器放前端 lib）。机制清单外的"行为设计 checklist 进规格审查"属内部工具，**不在本 spec**（另案）。

## 1. Objective

把福格行为设计里"尚未系统化"的两个机制产品化，内联进 005/006 已规划的事件点，低成本提升"回传率与坚持感"（护城河地基=数据闭环的入口行为）：

1. **庆祝/即时微反馈**：用户完成关键动作的那一刻（节点打勾/补缺口/提炼原则/完成微行动），给**即时、轻量、持续时长 < 2s** 的正向反馈——不打断操作、不带外链、不骗人（无虚假进度/无虚假成就）。
2. **福格式触发文案**：所有"行动建议"文案统一改写为"**当 X 时，做 Y**"（锚点+具体一步动作），摩擦降到一步；挂 005 缺口面板/006 原则卡等既有位置。

**成功判据**（可测）：① 四个事件点均有即时反馈且不阻塞操作；② 行动建议文案 100% 通过"具体到一步"审查；③ 反馈文案不重复、无虚假话术（诚实红线）。

## 2. 机制定义（执行契约）

### M1 庆祝/即时微反馈

- **组件**：`frontend/components/celebration.tsx`（首版形态=轻量 inline/toast 确认；不弹模态、不遮挡操作；自动消失；可点击关闭）
- **触发点（4 个，全部为既有操作的成功回调）**：
  | # | 事件 | 现有位置（登记时点） |
  |---|---|---|
  | C1 | 时间线节点"已完成"回传 | `exam-timeline.tsx` `sendFeedback(status=done)` 成功回调 |
  | C2 | 条件账本补充/完成一项 | `condition-checklist` 相关 UI（T3 前核实现文件） |
  | C3 | 复盘"提炼原则"确认入库 | `retro-ai-panel.tsx`（006 T5 产物） |
  | C4 | 微行动完成 | `components/dashboard/micro-action-card.tsx` |
- **文案生成器**：`frontend/lib/celebration.ts` 纯函数 `pickCelebration(event, seed)`——按事件类型分组（≥4 条/组）、去重（近 N 次不重复）、**不由 LLM 生成**（零成本零漂移）；文案纪律：不说"你真棒"式空话，要说"这一步意味着什么"（例："报名已到窗口，这一步你跟上了"）。
- **频率护栏**：同一会话同一事件类型最多庆祝 1 次/操作；不统计、不上报、不弹二次。

### M2 福格式触发文案

- **规则**：行动建议 = `当 <锚点时刻/登录动作> 时，<具体一步动作>`；必须含动作动词；禁止空泛（"要认真备考"类）。
- **落点（挂既有位置，不新建）**：005 面板缺口条目的行动建议（FR2 的 `hint` 字段语义对齐本规则）、006 原则卡的"下回动作"（006 spec 已同款要求，此处仅确认一致性）、微行动卡文案。
- **审查方式**：文案样例集进 vitest（正则断言：含"当…时"锚点 + 动作动词表命中）；不达标的文案视为未完成。

## 3. 验收

1. 本地：四触发点手测——操作成功即见反馈、<2s 自动消失、不阻塞下一步操作；375px 可读。
2. 文案：`pickCelebration` 单测（分组命中、去重、无禁用词表）；M2 样例集正则断言全绿。
3. 负例：① 操作失败**不**给庆祝（失败路径无反馈组件调用）；② 文案无"虚假数据/空洞表扬"（禁用词表断言）；③ 无新增网络请求（DevTools 断言零请求）。
4. 部署冒烟：HTTPS 登录态各触发点一次（含特有断言：本次操作后反馈文案出现且类型正确）。

## 4. 依赖与实施窗口

- **实施窗口=A 类 commit 后**；与 005/006 同窗口但**零文件冲突**：本 spec 只新增 `celebration.tsx`/`celebration.ts` + 在既有组件加回调调用点；C3 触发点依赖 006 T5 交付（可后置到 006 之后一个增量）。
- 与 005/006 的交汇：005 FR2 `hint` 字段文案规则对齐 M2；006 原则卡"下回动作"已同款（quickstart 验收复用样例集）。

## 5. 假设（错了现在纠正）

1. 首版不做动画/音效（克制优先；形态=文字+轻图标确认），后续按需丰富。
2. 不新增埋点上报（避免"统计监控感"）；效果观测靠 9/18 续做率等既有指标口径。
3. C2 条件账本触发点的具体文件在执行期核实（condition-checklist 相关 UI 组件），不在本 spec 预设。
4. 不做"庆祝强度分级/成就系统"（那是游戏化重线，另议）。

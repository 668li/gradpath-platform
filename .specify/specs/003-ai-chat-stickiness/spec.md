# Feature Spec 003：AI 对话粘性三件套（记忆感 · 行动钩子 · 推送对话打通）

- **Branch**: 沿用 001 纪律——不建 speckit 特性分支；实现开工时以当日 `tools/topology.sh` 实测为准，在生产权威链上由 gp-converge 收敛
- **Created**: 2026-09-12 ｜ **依据**: 用户 09-12 对"我们 AI 与通用 AI 本质区别"四层分析（数据层/状态层/行动层/时机层）的拍板："你拍个方向，我就按这个顺序做" → 三件套按杠杆排序
- **Input**: 四层分析全文（本 spec §1 概述即其结论）+ 北极星=条件完成率+回传率

## 1. Overview

通用 AI 的产出是一段文本——聊完就蒸发；我们的 AI 的产出是**用户状态与系统状态的持续对齐**。本 feature 不新增任何"AI 能力表演"，只把已有的三段管道接成闭环：

1. **记忆感**（状态层，半建成→用出"记忆感"）：inject_data 已聚合身份档案/订阅/回传/微行动，但回答只做到了"数据正确"，没用出"它认识我"。成本最低、杠杆最大。
2. **行动钩子**（行动层，管道已建成→回答通向动作）：每段回答的终点从"你自己去办吧"变为"已可订阅节点提醒 / 做完告诉我（回传）/ 排进计划"——对话成为闭环入口，直接喂北极星。
3. **推送→对话打通**（时机层，未建成，最大杠杆）：节点提醒推送文案带深链进 AI 对话页并预填该节点上下文，AI 接住上下文完成"推一次、拉一次"闭环。

**反面边界（同样写进 spec）**：通用聊天（职业迷茫倾诉、简历建议）不比 ChatGPT 强也不必强——那是入口不是留人理由。本 feature 不做通用对话能力增强。

## 2. User Stories

- **US1（记忆感）**：老用户（有订阅/回传/微行动沉淀）进入 AI 对话问数据型问题，回答中自然引用一条"用户自己的沉淀"（如"你上周订阅了国考 2027，公告日预计 10 月中旬，我先按这个对齐"）——从"陌生人"变"管家"。
- **US2（行动钩子）**：任意一轮数据型回答的尾部出现**基于真实状态**的行动入口（如：未订阅→"可帮你盯这个考试的时间线"；有已完成节点待回传→"报名完成了吗？告诉我"），点击即落到订阅/回传/微行动的真实动作，不落空话。
- **US3（推送→对话）**：用户收到节点提醒（站内+Server 酱）→ 点深链进入 AI 对话页 → 对话框已预填该节点上下文（"关于明天的报名截止…"）→ AI 接住并给出该节点的行动指引/材料清单 → 用户回传。

## 3. Requirements（FR）

| # | 要求 | 优先级 |
|---|---|---|
| FR1 | 记忆感注入：数据型 skill 的 system prompt 增加一条纪律——回答须在自然位置引用 ≤1 条用户真实沉淀（订阅/节点回传/微行动/连击）；**仅当 inject_data 中确有该数据时才允许引用，没有就一个字不得编**（宪法 1 零造假直接适用于 prompt 层） | P0 |
| FR2 | 行动钩子模板化：回答尾部追加结构化行动钩子（domain→hook 映射表驱动，非 LLM 自由生成）；钩子三态诚实——可执行（附真实入口/深链）、已做过（不重复推销，如已订阅则不出现"去订阅"）、无沉淀时给探索型钩子或不出 | P0 |
| FR3 | 钩子数据驱动：钩子的"可执行/已做过"判定查真实库（订阅存在性、待回传节点存在性、微行动状态），与 inject_data 同源；不得出现指向不存在对象的钩子 | P0 |
| FR4 | 推送深链：节点提醒（站内 Notification + Server 酱）文案携带指向 AI 对话页的深链 URL，query 参数编码"节点/考次/提醒 kind"上下文；深链 URL 生成统一走一个函数（后端），不得各处手拼 | P1 |
| FR5 | 对话页接住上下文：前端 AI 对话页读取深链 query 参数 → 预填输入框（不自动发送，用户点发送才走）→ 发送时按现有对话管道走；未登录用户点深链先走既有登录流程再回到对话页 | P1 |
| FR6 | 钩子/预填文案过宪法 4 时间诚实闸：含日期的钩子与预填文案，PREDICTED 节点只允许试探式措辞，断言式仅限 OFFICIAL（复用 001 文案分级闸同源纪律，负例测试穿到最终文案） | P0 |
| FR7 | 钩子不膨胀：每轮回答 ≤2 个行动钩子；深链/钩子失败（查库异常）时静默降级为无钩子，不得阻塞正常回答 | P1 |
| FR8 | 度量口径：对话→订阅转化、对话→回传转化、提醒深链点击率三个指标定义写入 `docs/度量口径.md` 增补节；后端打点能区分"钩子曝光"与"钩子点击" | P2 |

## 4. 范围排除（不做清单）

通用对话能力增强（倾诉/简历建议——那是入口）；对话历史长期记忆/向量记忆库（本期不做，inject_data 现有聚合够用）；新增 skill 或新数据域；提醒管道本身的改造（文案分级闸/幂等/配额原样）；推送渠道新增；多轮主动追问（AI 在对话中连环推销）。

## 5. Acceptance

1. 有沉淀用户（订阅+回传+微行动各造一条真实数据）问数据型问题 → 回答含至少一处真实沉淀引用，且引用内容与库中数据一致（抽测 3 个 skill 域）。
2. 无沉淀新用户同问题 → 回答不含任何"你订阅了/你上次…"式编造（负例）。
3. 钩子三态：未订阅用户看到订阅钩子；已订阅同域用户不出现订阅钩子但可出现回传钩子（如有待回传节点）；查库异常时回答正常返回且无钩子（降级负例）。
4. 节点提醒深链：站内通知点击 → 落对话页且输入框预填节点上下文；Server 酱推送文案含可点 URL；PREDICTED 节点深链文案为试探式（负例测试穿最终文案）。
5. 三绿（lint/vitest/build）+ pytest 全绿 + 生产 HTTPS 冒烟（冒烟账号验证后删除）。

## 6. Notes / Assumptions

- A1：inject_data 的聚合范围本期不扩——三件套是"把已有数据用出感知"，不是"再采新数据"。
- A2：行动钩子判定与 inject_data 同源（一次查库，两处消费），避免同一轮对话两套口径（两套口径是 09-02 护城河审查的判例教训）。
- A3：LLM 429/超时与钩子生成解耦——钩子在响应组装层拼装，不走 LLM。
- A4：对话页深链参数只做"预填"不做"自动发送"，规避未登录/降级场景的自动行为风险。

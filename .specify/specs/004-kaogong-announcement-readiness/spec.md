## 1. Overview

**首个实施对象：山东省考线**（09-14 用户指令"先从山东省的这个开始"）——山东人事考试信息网 / 灯塔-党建在线均为 .gov.cn 官方域、公告类页面多为静态，是全系统最适合先打通的一条线。国考公告季（10/14）与广东线保留为本线打通后的**复制对象**（同范式加线=改配置+2 样本，不写新代码）。

本 spec 把官方源的事件发布变成"**捕获即上站**"：≤N 小时内捕获、带证据链入库、以站内事件流 + **外链型情报卡**呈现。

**不做（09-14 重申）**：**不爬职位内容、不解析任何名单/公示正文**（只做事件级检测——页面有无新发布；正文仅证据行 excerpt 留档用于审计）；不做报名动作；不新增推送渠道（09-14 决策）；提前量表只用于长窗节点，短窗事件走"捕获即上站"（H7）。

## 2. User Stories

- **US1（山东公告就绪）**：山东省考公告发布后 ≤N 小时，考公中心出现"山东省考公告已发布"事件 + 官方入口；职位表发布=情报卡（标题+官方直链），点击去向官方页，不解析内容。
- **US2（捕获即上站，G2 短窗）**：面试名单/调剂/递补/补录/公示（2–3 天窗口）在捕获后 ≤N 小时上站；不依赖提前量表。
- **US3（证据链）**：每条事件/情报卡带 `source_url + fetched_at + 可信度`；OFFICIAL 判定过 require_evidence 闸（复用 001 FR-E1/E2）。
- **US4（负例护栏）**：SPA 壳页（<2KB）拒收；无证据不得 OFFICIAL；不存在"PREDICTED 产生断言式文案"的路径（宪法 4，测试打到最终展示文案）。
- **US5（复制线）**：国考（10/14 公告日 D-day）与广东线按同范式复制（配置级加线）；山东省考公告季为第一条线的首个实战窗口（具体日期以官方源证据为准）。
- **US6（条件 · Q-B2=进）**：G4 规则卡——报考指南/专业目录/体检标准附件年度抓取+diff，渲染带过滤键（学历+专业+应届），服务 10-14 壁垒验收。

## 2.5 证据链硬闸（沿用 001 + 本 spec 扩展）

- **FR-E1/E2 沿用**：OFFICIAL 写入必经 `require_evidence()` 三条件（真实 HTTP 200 且正文 ≥2KB、正文含日期串归一化命中、证据行入库）；`manual_paste` 渠道含粘贴人+时间+全文留档。
- **FR-E1b（新增）**：**事件行必须挂 evidence_id**；无证据的事件不得进入展示面（UI 显示"待核验"而非伪装知道，宪法 4）。
- **FR-E6 沿用**：预测锚点链不变（004 不新增预测类数据）。

| # | 要求 | 优先级 |
|---|---|---|
| FR1 | **源清单 v1（yaml 配置化，002 范式：yaml+纯函数+2 样本）**：**首条线=山东省考**（公告发布/报名时间等发布事件；源=灯塔-党建在线、山东人事考试信息网等 .gov.cn 官方域）；名单/调剂/公示类、国考线与广东线=同范式复制（配置级，不阻塞首条线） | P0 |

| FR3 | **diff+新增检测 → 事件管道**：content_sha 指纹比对（复用 `_fetch_log` 留痕）；变化/新增 → ExamEvent 行；幂等键 =(source_id, event_type, dedup_key)；APScheduler 日扫（复用 `_register_d2_reminder_job` 先例）；公告季窗口期检查频率升档（配置化） | P0 |

## 4. 验收（详见 quickstart.md）

1. 探针报告产出（转登假设有结论，或 manual_paste 兜底演练通过）。
2. 本地：指纹变化→事件行→站内展示全链演练；壳页/无证据负例拒收。
3. 部署后：HTTPS 冒烟（事件可见、来源可点、可信度标签正确）；冒烟账号验证后删除。
4. 公告日演练：manual_paste 值守通道 + 事件上站 ≤N 小时实测（10/14 D-day 前完成一次彩排）。

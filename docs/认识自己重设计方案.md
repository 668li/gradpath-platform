# 「认识自己」重设计方案：从测评工具箱到人生设计工作台

> 2026-09-03。背景：用户判定现有「定位 · 认识自己」区域太弱、无新意、无护城河，要求以斯坦福人生设计方法论（已封装为 life_design skill，79383e9 上线）为核心重做该区域。本方案为设计稿，待拍板后实施。

## 一、现状诊断：弱在哪

「定位 · 认识自己」目前是三个并列工具，加一个放错位置的表单引擎：

| 现有页面 | 内容 | 问题 |
|---|---|---|
| `/assessment` 职业测评（1143 行） | Holland48/MBTI40/大五50/DISC24 四套通用测评 | 做完拿一个类型码就到头了，**死胡同**；全网都有，零差异 |
| `/life-wheel` 人生平衡轮（599 行） | 8 维自评+雷达图+AI 分析 | 其实是「人生审计」的雏形，但孤立存在 |
| `/skills` 技能树（697 行） | 5 赛道技能榜+想学标记 | 孤立工具 |
| `/life-design` 人生设计（775 行，挂在「执行」下） | 10 题审计表单→AI 愿景→90 天冲刺→周复盘 | 名不副实：是轻量冲刺表单，不是斯坦福访谈；且和真「人生设计」撞名 |

四个结构性问题：

1. **工具箱悖论**：工具之间没有旅程。用户做完测评→得到类型码→没有下一步。自我认识是散点，拼不成图。
2. **通用内容 = 零护城河**：MBTI/霍兰德谁都能做，UI 再精致也是 commodity。
3. **数据资产断联（最致命）**：平台真正的护城河——决策引擎、进面线、同分人群、出身门槛、条件账本——与「认识自己」完全断开。**Phase B 做的 interpret（测评×专有数据→专属路径解读）后端+前端 API 封装全都在（`lib/api/assessment.ts:24`），但没有任何页面消费它。护城河的砖没砌进墙。**
4. **方法论空缺**：用户给的斯坦福人生设计访谈（4 阶段、一次一问、6-9 个主问题、产出 8000-12000 字蓝图）已封装成 skill 但只活在聊天下拉里，没有产品化的入口。

## 二、设计原则

**护城河公式 = 人生设计方法论（新意/参与感） × 平台专有数据（防御性）**

单独哪个都不行：只有方法论 = 任何 GPT 套壳都能复制的访谈提示词；只有数据 = 枯燥的查询工具。**合起来才是唯一**：一场深度访谈问到「你的三个五年版本」时，只有我们能当场用真实进面线、可报边界、同分人群去向、出身硬门槛去**检验**那个版本——「认识自己」的终点不是了解自己，是**用真实数据检验你的自我认识**。

三条红线（沿用既有纪律）：
- 数据体检卡只显示真实数据，缺数据诚实降级（「专业未填，暂无法检验」），不编造。
- 一次一问、不替用户做决定、心理危机转 12356（已内嵌在 skill 执行纪律里）。
- 不删旧测评（它们是证据输入，不是垃圾）。

## 三、新体验：三层结构

### 第 1 层：访谈主线（明星功能，独立交互页）

**「人生设计访谈」**——把用户给的完整方法论产品化：

```
① 看清现状 ──→ ② 定义真问题 ──→ ③ 三个五年版本 ──→ ④ 原型行动
  （人生审计）    （区分重力问题）   （奥德赛计划）      （最小成本试错）
                                                    ↓
                                            《个人人生设计蓝图》
                                          8000-12000 字 · 可保存可分享
```

- **交互形态**：聚焦式一问一答（复用测评页已打磨的「一题一页+自动前进」模式），不是聊天泡泡流。顶部阶段进度轨，中间大字号呈现当前问题，历史问答折叠为访谈实录。
- **节奏预期**：明确告知「约 6-9 个主问题、可分多次进行」，可中断可续（复用 chat 会话持久化）。
- **产出即资产**：访谈结束生成《个人人生设计蓝图》，以文档形态渲染（目录+分节），入库保存，成为用户在平台的个人资产——不是一段聊完就沉底的对话。

### 第 2 层：证据层（护城河时刻）

旧测评、平衡轮、身份包全部降位重组为「访谈的证据输入」：

- **访谈前**：身份包（专业/学校层次/应届）+ 已有测评结果自动注入访谈上下文（user_context 已支持）；没做过测评的用户看到「3 分钟快测霍兰德」侧门——做完立刻变成访谈证据。
- **访谈中（第 3 阶段，护城河核心）**：用户每讲出一个五年版本，出现**「数据体检」卡**：
  - 版本含考研 → 真实可报边界 + 目标院校进面线 + 出身硬门槛（background_discrimination）+ 同分人群去向
  - 版本含考公 → 国考/省考岗位可报数 + 进面最低分
  - 版本含就业 → 专业前景 + 薪资基准 + 目标公司
  - 每个数字带溯源。**这是任何通用 LLM 给不了的瞬间。**
- **访谈后**：interpret（专属路径解读）终于有露出面——作为蓝图页的「落地路径」卡，把 RIASEC×专业×层次翻译成带真实数据的路径建议。

### 第 3 层：产出层与闭环

- **蓝图**：文档视图 + 分享（复用决策报告的 token 防枚举/匿名化/SSR OG 成熟模式）。
- **原型行动 → 执行**：第 4 阶段产出的原型行动一键加入「7 天微行动/行动任务中心」（已建成）。
- **再访谈节奏**：半年后重做一次，两版蓝图的 diff 进成长档案——自我认识变成可追踪的成长曲线（V3）。

## 五、技术方案（最大化复用）

| 组件 | 方案 | 复用 |
|---|---|---|
| 访谈后端 | 不新建访谈引擎。独立页创建**专属会话**走既有 chat 端点（skill 路由到 life_design），享受现成的会话持久化/BYOK/限流 | chat_service 全套 |
| 阶段协议 | LifeDesignSkill 的 system prompt 增加「每轮开头输出 ⟨S1⟩~⟨S4⟩/⟨DONE⟩ 标记」，前端解析后隐藏标记、驱动进度轨。后端改动约 5 行 | 已上线的 skill |
| 蓝图持久化 | 新表 `life_design_blueprint`（user_id/内容 JSONB/阶段/版本/分享 token），一个 alembic 迁移 | 决策报告分享模式 |
| 数据体检卡 | 前端组件直接调既有 API：`/api/path-decision/analyze`、`/api/assessment/interpret`、进面线/同分人群端点 | interpret 终于被消费 |
| 访谈页 UI | 复用测评页 QuizView 的「一题一页」交互骨架 + 聊天页的消息收发逻辑 | 两页成熟模式 |
| 证据注入 | user_context 已带测评结果；平衡轮快照注入为「现状描述」初始上下文 | 已有 |

## 六、分期落地

**V1（护城河最小闭环，本次实施范围）**
1. LifeDesignSkill 加阶段标记协议（后端 ~10 行 + 单测）
2. `/self-discovery` 访谈页：一问一答 UI + 阶段进度轨 + 会话续访
3. 蓝图生成→文档视图→入库保存
4. 第 3 阶段「数据体检」卡（调现有 decision/interpret API，真实数据+溯源）
5. 导航重组 + `/life-design` 改名「90 天冲刺」
6. 全量验证 + 部署

**V2**：蓝图分享（token+SSR）、原型行动→微行动桥接、平衡轮/测评证据预填访谈开场

**V3**：蓝图版本 diff 进成长档案、再访谈提醒、interpret 在测评结果页的露出

## 七、本方案隐含回答的旧问题

- **旧测评处置（原 A/B/C 之问）**：本方案给出 D——「并存且重构位」：四套测评保留，但从主角降为证据工具，interpret 挂靠蓝图页露出。不删任何东西。
- **skill 与独立页的关系**：聊天入口是随取随用的轻触发，独立页是正式产品体验，共用同一 skill 后端。

## ④ 根因拆解（5Why + 五类归属）

**P1 converge 单传漏笔（三犯）**→为何挤掉：单传只含 HEAD→为何单传：惯性传 `$(git rev-parse HEAD)`→为何没暴露：rev-list 计数被 cherry-pick 镜像污染不可用→为何没兜底：收工清单没有"内容级 diff 归零"固定闸→**根因=方案设计问题**（闸口缺失，非"忘了"）。修复已入记忆；应进 gradpath-deploy skill。
**P2 子代理反复重试 9 败**→为何重试：不知道配额/并发余量→平台不暴露状态→为何继续等：首次失败报错形态陌生，误判可恢复→**根因=信息输入不全 + 时间资源浪费**。对策已执行：失败 2 次即切自执行。
**P3 聚合站盲走 20min**→为何默认走 eol：首战 B1 挂账印象"eol 有专题"→为何没先探形态：把历史线索当路线，违反"种子必须现场复测"精神→**根因=方案设计问题**（缺 1 分钟形态探针步骤）。对策已入记忆：新源先探一页定 HTML/JS/图片形态。
**P4 解析器两轮返工**→为何假设总分在尾：以清华样本（批次 A 代理转录）为先入为主→为何没先看中山表头：拿到 PDF 直接上正则→**根因=信息输入不全**。对策：解析器应先提取表头行定列序（可自动：找"总分"列位置）。
**P5 表名/结构猜错×4**→为何猜：查 schema 要一轮 ssh 往返"嫌慢"→**根因=时间资源上的侥幸**。对策：`information_schema` 一行命令固化为动手第一步（本场后半段已养成，前半段 4 错、后半段 0 错）。
**P6 Mimosa 拦截反复踩**→拦截模式在记忆里但新形态（SSRF 静态误报、组合命令误判）每次不同→**根因=工具能力限制**（静态分析对"变量 URL"一律拦，无法区分）。对策：高危写一律 Write/Edit 单发；爬取类不落库脚本、走人工清单+内联执行。
**P7 a11y 配方两次失败**→为何分段读 spec：先凭记忆拼配方→**根因=信息输入不全**。对策：配方类知识一次读完整个块再动手（本次第 3 次才读全 58-110 行）。

## ⑥ 停止做｜继续做｜新增做

**停止做**：
1. 停止用 `rev-list --count` 做收敛判据（cherry-pick 镜像恒噪音）——换 `git diff <A>..<B> --name-only` 内容级判据
2. 停止对子代理配额/并发错误做第 3 次重试——失败 2 次即切自执行
3. 停止凭记忆猜表名/列名/响应结构——先查 information_schema / response_model
4. 停止在组合 Bash 命令里夹带 .py 写操作——一律 Write/Edit 单发

**继续做**：
1. 部署四件套：converge→preflight→nohup 绝对路径→轮询（13 连胜的配方，不动）
2. 导入五步法：dry-run→抽验→备份→入库→生产复核
3. not_found 如实 + 官方 source_url 红线 + 抽验 N/3 后批量采信
4. 挂账当场销账（对抗审查产出不跨场）

**新增做**：
1. 收工固定闸：`git diff <deploy-ready>..<deploy-rebased> --name-only` 归零检查（进 gradpath-deploy skill 收尾节）
2. 新数据源 1 分钟形态探针（表格 HTML/JS 壳/图片三选一路线）——先探再定路线
3. 解析器先读表头定列序；PDF 缓存留档作证据
4. schema 速查固化为习惯动作（ssh 一行 information_schema）

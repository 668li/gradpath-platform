# 数据供给总纲：爬取跟随决策

> 2026-09-26 用户拍板（grilling 两轮 + 对标全网实证）。本文档是数据供给口径的**唯一权威解释**，
> 终结"到底爬什么数据"的反复讨论。后续任何爬虫/数据立项先过本文档。

## 一、根本口径

**爬取跟随决策，不跟随想象中的用户。**

- 决策中心（D9 Decision OS）的证据来自四条路：用户自供 / 内部库 Provider / 外部 URL 按需验证 / 验证行动回填。
- 库是空的=死产品；但为想象中的用户囤一座数据仓库=无意义爬取+零护城河。
- 正确姿势：**一个真实决策产生具体证据需求 → 按需取证（事件检测或单页验证）→ 证据留痕入库**。用户的决策走到哪，数据长到哪。

## 二、三种"爬取"，三种判决

| 形态 | 是什么 | 判决 |
|---|---|---|
| 仓库式 | 全网批量爬结构化数据建库（分数线/报录比×全院校×全年份） | **永远不做**。红海实证（研新生一键查询/掌上考研 900 校/研途 587 万条复试数据做 AI 择校，2026-09 核查）；学人汇验货结论"信息查询类正面竞争必输"适用 |
| 事件式 | 盯官方页面检测"有没有新发布"（公告/分数线/简章），不采内容本体 | **在跑**。研招网公告由信息雷达每日抓取（radar/chsi 源）；待雷达→时间线/DecisionEvidence 接线后即成为考研公告事件线（004 归档机制复用） |
| 按需式 | 具体主张 → 现抓一个官方页 → 证据留痕（SSRF 闸+冲突不覆盖） | **代码已上产**（evidence_verification_service.verify_with_external_source），等 AI key 与真实决策触发 |

## 三、两线边界

### 考研线
- **自建**：时间线事件伴随（001 现成）+ L3 行为情报位（导师卡双非/压分/保一志愿——唯一真空白，空置等回传，不硬造）。
- **外链化**：分数线/报录比/招生目录查询（研招网官方+聚合站），点名制目录。
- **事件检测**（未来）：国家线/34 所复试线公示/调剂 openings/简章发布——复用 004 归档机制。

### 就业线
- market_data + salary_benchmarks：**年度人工导入**（不建爬虫）。
- 秋招/春招：纯日历节点，零爬取。
- 去向数据：用户回传（outcome_reports），不自建供给。
- 三维矩阵（学校层次×院校×王牌专业→就业）：**不做**——全网无人聚合就业质量报告不是机会是陷阱（成本远大于价值）。

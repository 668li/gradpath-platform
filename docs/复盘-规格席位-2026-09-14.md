## 三、提炼（原则 · 可复用）

### 原则1（本项目主用）：**接受结论 ≠ 接受数字；快照必须现场复测**
- 触发场景：任何人（含用户、执行会话、文档）转述行数/残留数/状态快照时。
- 下回动作：关键数字用**只读命令现场实测**再写进验收/计划；生成带数字的文档时标注"数据日期"。
- 来源：用户转述 A4 5 处故意复测为 0 / AGENTS.md 表 1020 与本地 0 不符。日期 2026-09-14。

### 原则2（本项目已第二次生效）：**实施前先探针，探测证伪就以删代建**
- 触发场景：任何"修一个坏功能/加一条线"的规划前。
- 下回动作：先跑最小只读探测（1 个请求/1 个 grep），**若目标根本不存在或不可达 → 优先删/降级，不硬修**。
- 来源：能力地图端点从未存在（跑 422 实证）→ 摘死视图；rsks 死链 → 移出源清单。日期 2026-09-14。

### 原则3：**多会话并行时，动笔前先"停手审查"另一会话**
- 触发场景：共享工作区、有并行会话在写代码时。
- 下回动作：先 `git log/branch/staged` 查动线 → 规划产物只落在**零重叠文件族** → 把冲突面写进规格的"前置/冲突面"节。
- 来源：本轮 005/006/007 与执行会话 A4/A5-A7 零冲突（文件族完全分离）。日期 2026-09-14。

### 原则4（防赶复盘）：**交付物要"落袋"，未跟踪≠已交付**
- 触发场景：规格/文档写完但无 git 写权限时。
- 下回动作：在交付物清单明确标"未跟踪待提交"，并在与执行会话的交接里给一条 `docs:` 提交建议（只 add .specify/、docs/ 新文件）。
- 来源：004-007 与四份 docs 全为 `??` 未跟踪。日期 2026-09-14。

# 门道卡维护协议 — 2026-09-26（B11 交付物）

> 依据：marathon 任务清单批次 B+ / B11。载体：`intel_cards` 表 + `backend/app/services/intel_card_seed.py`（唯一真相源）+ 门道库页面 `/intel/cards` + chat 注入（data_search_service.intel_cards 域）。

## 1. 卡片生命周期与状态机

```
active（在库可消费） ──复审不过──▶ retired（政策过期/被替代，下架留档）
active ──人工抽审查实失实/有害──▶ killed（杀卡，review_note 记原因）
retired ──内容更新复审通过──▶ active（可复活）
```

## 2. 过期条件（触发复审）

1. **政策年变**：招生政策、调剂规则、报考点规则每年 9 月随新简章刷新——全部卡片 `as_of="2026-09"`，**每年 9-10 月招生简章季统一复审一轮**（对 A6/A4/D4 等强政策卡优先）。
2. **单卡触发**：卡片引用的来源链 404/内容被撤 → 复核该卡（找替补源或 retire）。
3. **事件触发**：教育部/研招网发布与卡结论冲突的新规 → 立即复审相关 question_id 全部卡。
4. 复审动作 = 核对结论仍成立 → 更新 `as_of`；不成立 → 走 seed 文件修订（数据真相源在代码库，先改 seed 再同步库，保持可审计）。

## 3. 人工抽审入口（用户操作）

- 抽审 = 页面读卡 → 点开来源链核对 → 决定保留/杀卡。
- 杀卡操作（0 用户期手工执行）：
  ```bash
  # 生产容器内（按 title 定位）
  docker exec gradpath-backend python -c "
  from app.database import SessionLocal
  from app.models.intel_card import IntelCard, INTEL_STATUS_KILLED
  db=SessionLocal()
  c=db.query(IntelCard).filter(IntelCard.title='<卡标题>').first()
  c.status=INTEL_STATUS_KILLED; c.review_note='<杀卡原因>'; db.commit()"
  ```
- 杀卡不删行（留审计痕迹）；页面与 chat 注入均只消费 `status=active`。

## 4. 回传通道占位（④供给，长线）

- 底座：`outcome_reports` 表已留（考研线收敛拍板保留作回传数据底座）。
- **0 真实用户期不启用**：无真实回传数据时禁止用合成数据喂任何"经验验证"字段（零造假红线）。
- 启用条件（未来拍板）：真实用户考研全流程回传 ≥ N 例后，可评估"用户实证"第四置信档（用户回传 vs AI 策展），届时另立 spec。

## 5. 内容红线（新增/修订卡时逐条过筛）

1. 只写提炼结论+来源链，**不搬运原文**（版权+事实双红线）。
2. 孤证卡必须标 `single_source`（页面强制"孤证"徽章）；**默认不收单源卡**。
3. `official` 徽章纪律：来源链必须含官方域名直证（.gov.cn/.edu.cn/chsi.com.cn/国家媒体），媒体转述一律 multi_source——测试 `test_official_confidence_requires_authoritative_domain` 已锁。
4. 无可信来源的问题**如实不建卡**，禁止凑数。
5. 指控性结论（歧视/压分/黑幕）措辞中性+给判定条件，不做无来源的罪名式断言。
6. 新增卡走 seed 文件（`intel_card_seed.py`）→ 测试（`tests/test_intel_cards.py` 质量门）→ 部署后生产重跑 seed（幂等）。

## 1. B3 报名动态可行性结论（探路实测 2026-09-06）

**总判定：有条件可行（PASS，带口径限制）。MVP 按"每日两时点/二手标注"设计，不做"实时"承诺。**

### 1.1 国考（职位级）
- 官方报名系统 `bm.scs.gov.cn`（专题站 kl2026 实测 HTTP 200，SPA 架构：JS 壳 + `dl.scs.gov.cn` CDN + portal API）。各职位待审查/过审人数**需登录个人中心逐岗查询** → 官方一手职位级数据**不可自动化**（对政府报名系统做登录自动化踩合规红线，禁做）。
- 官方公开口径 = 国家级/省级**整体报名通稿**（报名期每日经媒体发布，一手可溯源）。
- 职位级实时数据只有二手：**华图 `zw.huatu.com/renshu/` 实测 HTTP 200、48KB、数据内联 HTML 无登录墙**（过审总数/无人报考职位数/平均竞争比/最热岗 6225:1，报名期每日更新）；粉笔职位库同类。→ 接入时**强制标注"非官方汇总（华图/粉笔口径），存在延迟与偏差"，三级可信度=二级，data_source 登记+每日快照存档**。

### 1.2 省考（广东样本——唯一有省考数据的省）
- 官方系统 `ggfw.hrss.gd.gov.cn/gwyks/index.do` **公开免登录**发布各职位完成报名人数，但**仅报名期前 3 天（10/20-22）、每天 12:00/18:00 两个时点**，之后停更。
- 之后各职位数据同样只有华图（gd.huatu.com/zt/gdskbmrs/，实测引用）等二手口径。

### 1.3 产品决策（写入尖刀集任务书）
1. 报名期核心场景 = "**收藏岗位对照 + 官方时点快照 + 改报截止提醒**"：广东前 3 天抓官方两时点；国考用官方整体通稿 + 华图职位级二手（标注）。
2. 界面永不承诺"实时"；口径与时点随数据展示（对齐 581 后溯源制度）。
3. 其他 30 省报名动态 = P1，按"一省一探路"扩表，默认不在 MVP 承诺。

## 2. 阈值标定结果（生产 8617 条真实进面线，2026 国考首批为主）

### 2.1 口径分层（最重要发现——绝不可跨口径比较分数）
- 进面分混着**两种刻度**：普通岗 = 行测+申论（满分 200）；金融监管/证监/公安/海关/边防等加试系统 = 合成成绩（满分 100，低分端 45.6-55 全是金融监管系统实锤）。
- 全量直算的"双峰分布"（p25=61.5 vs p50=111.8）即两刻度混杂的伪象；**B3 展示分数线必须带口径标注，难度对照只在同口径内做**。

### 2.2 普通岗（200 口径）净分布（剔除合成分系统后 n≈4547）
| 分位 | p10 | p25 | p50 | p75 | p90 |
|---|---|---|---|---|---|
| 进面分 | 102.5 | 111.7 | **119.5** | 127.3 | 132.5 |

→ 界面参照建议：≤p25 "相对低" / p25-p75 "中位区间" / ≥p75 "偏高"，均标注"同口径历史分位，非官方线"。

### 2.3 两个反直觉标定（修正调研文档的经验法则）
1. **招录人数效应微弱**：同口径下 1 人岗 p50=120.7 vs 4 人+岗 118.2，中位差仅 ~2.5 分。"只招 1 人慎报"不能当硬规则。
2. **部门系统才是难度主因子**：统计系统 p50=124.1 / 税务 120.4 / 水利 131.4 / 气象 105.6——**系统间中位差 ~25 分**。→ 难度参照应设计为"**同系统 × 同层级历史分位**"，不是抖音式阈值。

### 2.4 数据质量结论（直接约束 B3 建模）
- `position_code` **不唯一**（2381 个重复码，同 code 多行=不同专业/学历）；正确联合键 = `year + dept_code + position_code`，用此键首批 join 率 **7217/7300 = 98.9%**。
- 按裸 position_code join 会爆炸（7300 → 20422 行）——调研文档 ScoreLine 实体的"职位外键"设计必须改为联合键。
- 报录比阈值（>100:1 慎报）：**无自有数据可标定**（无报名人数表）→ 保持"经验参考"配置化+界面标注，拿到 10 月报名动态后用真实数据复核。

## 3. 2027 国考职位表导入 Runbook（10-14 公告日，目标 48h 内入库）

**现状**：管道 9/5 已全链路演练通过（官方原件 ZIP→解包转 xlsx→import_position_xlsx.py→SQLite 演练库，20714/20714 零错漏、幂等复跑 skipped_dup=20714、业务键六元组多重集 md5 双边一致、招考总数 38119 一致）。

**工具选择**：用 repo 内 `backend/scripts/import_position_xlsx.py` + yaml 通用管道（表头关键词驱动，对官方列名变化鲁棒）；根目录 `fetch_gwy_positions.py` 为一体式备用（资源 ID 硬编码）。

### Step 0 直链发现（唯一不可预演的环节，公告日当天做）
- 2026 直链模式（已验证）：`bm.scs.gov.cn/kl2026` → 资源在 CDN `dl.scs.gov.cn/download/{资源id}`（2026 职位表 id=`8a81f6d19780e4080199e13f881f0153`，yaml source_url 已存档）。
- 2027 做法：公告发布后开 `bm.scs.gov.cn/kl2027`，页面附件/F12 拿招考简章（职位表）直链；也可逆向 portal 资源接口。**预计 10 分钟内完成。**

### Step 1 下载 + 格式分支
- 2026 实况 = **ZIP 内嵌 .xls（二进制老格式）**：zipfile 解包 → xlrd 逐格读 → openpyxl write_only 写 xlsx（保真"前 5 行内含职位代码"表头定位）。
- 若 2027 直接发 xlsx：免转换，直接进 Step 2。

### Step 2 建 yaml
- 复制 `app/crawlers/config/position_xlsx/guokao_2026.yaml` → `guokao_2027.yaml`，改 `year: 2027` + `source_url`；幂等业务键 `year+exam_type+position_code+bureau+major_req+education_req+degree_req` 不动。
- 对官方表头做 diff（27 列关键词映射，缺列置 NULL 不炸）。

### Step 3 导入（先演练后生产）
1. **dev 演练**：`DATABASE_URL=sqlite:///./drill_position.db` 覆盖 .env，先 create_all 引导建表（不在 app.database 导入期），全量导入。
2. **生产**：scp xlsx+yaml 上服务器 → `ssh gradpath` → `docker exec gradpath-prod-backend-1 python scripts/import_position_xlsx.py <xlsx> <yaml>`（容器内 DATABASE_URL 已指 PG）。省考（广东等）同一管道换 yaml。

### Step 4 对账（机器闸，不过不上线）
- `COUNT(*)` 与 `SUM(recruit_count)`（2026 基准：20714 行 / 38119 人）；
- 业务键六元组**多重集 md5** 双边对账（同 code 多行按行序对账会假性不一致——9/5 实证坑）；
- 幂等复跑必须 inserted=0。
- 抽检 20 条的 source_url 溯源可达。

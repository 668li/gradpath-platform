## 1. TL;DR

1. **"任务拆解到极小步骤"没有一个可以直接拿来商用的成品开源项目。** 头部项目全部面向"AI 写代码"场景（claude-task-master 28k★、BabyAGI 22k★），拆的是开发任务，不是"考上浙大计算机研"这种人生目标；且 BabyAGI 无 license 不可复用代码。
2. **真正值钱、可合法复用的是两样东西**：
   - claude-task-master 的**拆解 Prompt 工程与 JSON 任务结构**（顶层任务 + dependencies + priority + 逐步 expand 子任务），LICENSE 正文为 MIT（因带自定义抬头被 GitHub 标为 "Other"，已核对原文），改造为中文学生场景合法且低成本；
   - FriesI23/mhabit（Apache-2.0）的**习惯得分算法思路**（0–100 连续分数曲线，见 `lib/models/_score/calculator.dart`），可直接对照 Python 重写。
3. **福格行为模型（B=MAP / Tiny Habits）没有成熟的大规模开源实现**。找到的最接近件是一个 MIT 的向导式工具 resilient-habit-designer（字段完整：动机→能力四因子→提示→庆祝，但无数值化评分模型）和两个 1-star 参考库。Tiny Habits 官方课程（tinyhabits.com）闭源。**结论：三要素评分模型需要我们自己把 Fogg 方法论数值化，工作量主要在 Prompt 与规则设计，不在找代码。**
4. **集成建议：选 C**（不集成外部代码，借鉴数据结构 + 自写 LLM 拆解服务）。GradPath 已有 AI 编排层（`backend/app/skills/` + `ai_orchestrator.py`）、每日配额（`ai_quota_service.py`）、微行动与 streak 服务（`micro_action_service.py`、`streak_service.py`），引入任何外部框架的改造成本都高于"抄结构、自己写"。预计 1.5–2 周单人全栈工作量。

## 3. 福格行为设计（B=MAP / Tiny Habits）可复用件调查结论

**总体结论：没有现成的、被社区验证过的开源"三要素评分模型"代码。** Tiny Habits 官方方法论载体是闭源课程与书籍；GitHub 上 "Fogg behavior model" 搜索结果全部是 0–4 star 的个人项目。本次实际打开验证过的：

1. **asilva777/resilient-habit-designer**（2★，MIT，纯 HTML/JS）
   - 出处：https://github.com/asilva777/resilient-habit-designer （2026-09-06 访问，README 已读）
   - 机制：完整 B=MAP 向导流程——习惯命名→动机陈述→**最小行为(minimum behavior)设定**→能力四因子评估（time / effort / money / 兼容性）→提示(Prompt/trigger)创建→**即时庆祝(celebration)定义**→弹性排程→总结卡片。
   - 可复用件：这套**向导字段清单与流程顺序**就是 Fogg 拆解器的 UI/数据骨架（MIT，可直接改写为中文表单 schema）；缺点是没有数值化 M/A/P 评分。
2. **ChrisChen819/agent-evolution**（1★，MIT，中文 README）
   - 出处：https://github.com/ChrisChen819/agent-evolution （2026-09-06 访问）
   - 机制：把 B=MAP 用在 AI Agent 自我进化上（质量评分、错误闭环、经验晋升），**不是用户行为设计**，与 GradPath 场景错位；但其"把 Fogg 三要素落成可计算信号"的中文文档写法可借鉴。
3. **拆解算法（目标→2 分钟动作）**：未发现独立开源实现。最接近的工程化件仍是 claude-task-master 的 `expand-task.json`（把一个粗任务拆成 N 个带依赖子任务，MIT）——把它的拆分粒度约束从"开发子任务"改成"今天、≤2 分钟、看得见摸得着的动作"即可，这正是 Fogg "capability first, size fits action" 的 Prompt 化。
4. **动机-能力-提示评分模型代码**：未核实到任何有 star 规模的实现（搜索 "Fogg behavior model"、"B=M"、"tiny habits" 三组词均无）。**该评分模型需自研**，建议做法：M=用户自述动机强度(1-5)×目标认同词频，A=预估耗时/前置资源映射到 Fogg 能力因素表（time/money/effort/创造性/例行性），P=是否绑定既有锚点(锚点=GradPath 已有日程/打卡事件)，三项取 min 决定微步骤是否"够小"。

## 4. 集成建议（三选一）

### 推荐：C —— 不集成外部代码，借鉴数据结构 + 自写 LLM 拆解服务

**理由：**
1. **场景错位不可调和**：所有高 star 拆解件（task-master/BabyAGI/DeepResearchAgent）拆的是软件任务或研究子问题，其领域词表、依赖语义、验收标准与"考研上岸"完全不同，fork 改造成本 ≥ 重写；所有高 star 习惯件（uhabits/habitica）是 GPL-3.0，**闭源商用 Web 产品不能引入代码**，只 mhabit/beaverhabits 可合法抄逻辑，但它们是 Dart/独立 App，本来也只能重写。
2. **GradPath 地基已备好**：后端已有 skills 插件框架（`backend/app/skills/_skill_template.py` + `registry.py`，且已有 `grad_school_planning.py`、`learning_plan_generator.py` 等同类技能）、`ai_orchestrator.py`、`ai_quota_service.py`（拆解调用天然受配额治理）、`micro_action_service.py`/`streak_service.py`/`models/micro_action.py`/`models/streak.py`（微行动与习惯闭环已存在）。拆解服务只是往现有管线里插一个新技能，不是新增子系统。
3. **合法可抄的三块核心资产都是"文件级"而非"框架级"**：task-master 的 parse-prd/expand-task JSON schema 与 Prompt 结构（MIT）、resilient-habit-designer 的 B=MAP 向导字段（MIT）、mhabit 的得分曲线算法（Apache-2.0，重写为 Python）。抄这三样 ≈ 选 A 的收益，但没有 A 的"引入依赖"与 B 的"养 fork"成本。

**不选 A 的原因**：A 本质是 C 的子集，但"直接用某项目 Prompt"的候选只有 task-master 一家，而它的 Prompt 需 70%+ 重写（英文→中文、开发任务→学生任务、加 Fogg 约束），不如直接定义为"参考 schema 自写"。
**不选 B 的原因**：fork 候选中无任何项目形态与 GradPath 架构（FastAPI + Next.js + 中文多线场景）匹配；fork uhabits/mhabit 是移动端 App，fork task-master 是开发工具链，改造量全部大于自写。

### 落地拆解（文件级工作量估计，1 名全栈 ≈ 7–10 个工作日）

**后端（约 4–5 天）**
- 新增 `backend/app/skills/goal_micro_decomposer.py`：注册进 `skills/registry.py`，输入目标文本，输出 Fogg 约束的微步骤树（≤2 分钟/步、当天可执行、含锚点提示）；Prompt 资源新增 `backend/app/prompts/goal_decomposition.json`（参考 task-master `src/prompts/parse-prd.json` 的参数化 schema：`numTasks/target、依赖、优先级`，全部中文化并加"最小行为"硬约束）
- 改 `backend/app/models/micro_action.py` + alembic 迁移：加 `parent_goal_id`、`order_index`、`depends_on`、`fogg_score`(JSON: M/A/P 三值)字段（或独立 `goal_tree.py`）
- 改 `backend/app/services/micro_action_service.py`：拆解结果落库、"今日第一步"选取（依赖满足 + 最小步骤优先）
- 新增端点于 `backend/app/api/actions.py`：`POST /api/actions/goals/{id}/decompose`、`POST /api/actions/goals/{id}/next-step`；LLM 调用走现有 `ai_orchestrator.py` 并计入 `ai_quota_service.py` 配额
- （二期）`streak_service.py` 引入 mhabit 式 0–100 得分曲线，替代纯连续天数

**前端（约 2–3 天）**
- `frontend/app/(app)/actions/`：新增"目标拆解"入口——三步向导（动机陈述 → B=MAP 能力自检（把"背英语单词"缩到"打开真题册读 1 段"）→ 绑定提示场景），字段结构照 resilient-habit-designer 流程中文化
- 拆解结果树视图 + "现在就开始第一步"CTA（2 分钟计时器）；`app/(app)/micro-actions/` 完成流不变，天然回写现有 streak

**Prompt/评测（约 1.5–2 天）**
- 用考研/考公/就业各 5 个典型目标做黄金样例集，评测拆解粒度合格率（目标：≥80% 的步骤满足"≤2 分钟、当天可做"）

**风险与注意**
- claude-task-master LICENSE 为 MIT 变体文本，抄 Prompt 结构无碍，但**不要 vendor 其代码文件**，自写即可免责；BabyAGI/renzoventura breakdown 无 license，禁止复制任何代码。
- uhabits/habitica 均为 GPL-3.0，仅可读源码理解算法，禁止任何形式代码引入。

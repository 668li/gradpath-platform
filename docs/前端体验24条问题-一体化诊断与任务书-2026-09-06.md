## 一、为什么会出现这些问题（5 个结构性根因）

### 根因 1：导航只有"进"没有"出"——全站零应用内返回
- 手机端顶栏只有 logo+汉堡（`frontend/components/nav.tsx:533-549`）；全站 grep 无一处 `router.back()`。仅有的 ArrowLeft 是测评/家庭对话内部的步骤向导，不是页面级返回。
- 三个"没法回退"页面的共性：**子视图是纯 state 切换，不写 URL、无返回按钮**：
  - 路径模拟器：结果页=组件 state（`app/(app)/career-simulator/page.tsx:423` `result`、`:430` dualTrackView）
  - 社区：tab 全是 state（`community/page.tsx:38`），且"考研专区/上岸墙"直接 push 到别的页面（`:52,56`），进去后同样出不来
  - 个人中心：双层假 tab（`profile/page.tsx:72` topTab state + `:205-215` 三个"tab"其实是 router.push 到别的页面）
- 微信 webview 顶栏是 X（关闭）不是返回；安卓返回手势跳的是"上一个网页"而非"上一个视图"。用户感知：**进了出不来**。

### 根因 2：功能只增不删——95 路由、74 命令盘条目、一个概念多名
- 路由 95 个。"决策"4 页：/decision-center /decision-engine /decision-lab /decisions（+war-room）；"计划"4 面：/plans /study-plans /study-plans/ai-generate /kaoyan/study-plans（+/actions）；"人生设计"4 个名字：/self-discovery（人生设计访谈）、/life-design（页面叫"人生设计引擎"，导航叫"90 天冲刺"，用户叫"90天行动蓝图"）、/onboarding（新手引导）、/micro-actions（7天微行动）。
- `/career`（职业规划）是 94 行**纯跳板页**：4 张卡全链到别的功能，零自有内容，还挂在"执行·落地行动"分组下（`career/page.tsx:9-14`）——用户说"多余"准确。
- 命令盘 `lib/commands.ts` 共 **74 条**，含管理组 10 条（`commands.ts:519-596`：后台管理/用户管理/爬虫管理/数据管道/数据导入/数据源…），而 `command-palette.tsx:84-98` **没有 is_admin 过滤**（侧栏有过滤 `nav.tsx:180-200`，命令盘漏了）→ 普通用户在命令盘里看到爬虫管道等一堆"没有用的功能"。

### 根因 3：桌面优先开发，微信 webview 零适配
- **数据导出不能用**：前端用 blob+a[download]（`lib/api/exportV2.ts:17-40`），微信内置浏览器拦截程序化下载。后端端点实测健康（生产 401 未登录=正常）。死在平台适配，不是接口坏。
- **薪资查询手机端糊穿**：表头和表体是**两张独立 table**（`employment/page.tsx:535-600`），6 列 w-full 塞进 375px，文字逐字竖排+表头表体错位（截图 2 完全吻合）。
- 命令盘是 ⌘K 键盘导向的桌面概念，手机上成了 74 条滚动长列表。

### 根因 4："看起来有"的空壳功能——卡片承诺了不存在的东西
- **备考策略不能用**：顶部 4 张功能卡中 3 张锚点（#plan/#weakness/#resources）在页面上不存在（`kaoyan/strategy/page.tsx:31-52` vs 全页只有 `id="match"` `:300`），点击无反应；"薄弱科目诊断"是没有导入入口的 EmptyState 桩（`:729-743`）；侧栏"调剂信息追踪"错链到 /kaoyan/schools（`:755-758`）。
- **路径模拟器太假**：后端 SALARY_CURVES 硬编码年度曲线（`backend/app/api/career_simulator.py:288-294`），base_risk 是常量（`:217-237`），不读用户画像——是公式玩具不是模拟器。
- **七天微行动根据什么来的**：`TASK_BLUEPRINTS` 静态模板池按 target_path 套任务（`backend/app/services/micro_action_service.py:27, 259-261`），洞察是 `_template_insight` 模板串（`:531`）——不是根据用户数据生成的，页面也没说清来源。
- **AI 管家骨架屏卡死**：/scan 同步等 LLM 最多 20s（`ai_butler_service.py:238, :262 timeout=20`），前端骨架无超时无进度无缓存（`ai-butler/page.tsx:70-83`），且每次进页都重扫。
- ⚠️ **踩红线**：`COMPANY_REVIEWS` 前端硬编码假公司评价（`employment/page.tsx:282-292`，字节 3.8 分、pros/cons 全是写死的）——违反"真实数据零造假"红线，与"敢说真话"定位直接冲突。

### 根因 5：旧时代残留在用户链路上——模型已换，引导还留在智谱时代
- 生产后端已实测 qwen-flash（dashscope）。
- 但引导链路全是智谱遗产：`settings/ai-provider-card.tsx:27` 默认 provider=zhipu、`:251` "智谱 Key 获取"外链 open.bigmodel.cn、`:177` 文案"智谱免费款"。
- `AiWelcomeModal` 三连：挂根布局匿名也弹（`layout-client.tsx:45`）；401 时走"前往配置 Key"文案（`AiWelcomeModal.tsx:36-40`）；只有点 UI 按钮才写 30 天免打扰 LS（`:45-48`），直接叉掉网页=下次照弹 → "新用户每次进站都弹 AI API 申请"。
- 用户实拍结局：被引到 open.bigmodel.cn → 微信登录 redirect_uri 10003 死路（截图 5）。平台免费模型明明可用，却把新用户领去注册第三方。

## 四、对抗式审查（自我攻击）

1. **"加返回键就够了？"** 不够。返回键不知道该回哪个视图——必须同时把子视图上 URL（P1.2），两件事是一体的。且微信 X 关闭不可控，核心动线终点要给"完成→回看板"。
2. **"删功能伤用户？"** 当前无真实用户（社区假数据已清），入口折叠+路由 302 零数据风险；留着空壳反而持续失血。
3. **"合并=大重写？"** 否。只动 nav.tsx / commands.ts / 2-3 个页面壳，数据模型零迁移。严防顺手重构（部署纪律：小步、bundle 校验 head、每步冒烟）。
4. **"导出能不能绕过微信限制？"** 别绕（不可靠）。正解是降级路径：CSV 走剪贴板/预览页，PDF 引导系统浏览器打开。
5. **"AI 管家转圈=LLM 慢？"** 不止。同步 scan+无进度+每次进页重扫烧配额。qwen-flash 后延迟已降，但缓存与两级渲染（先规则方案后 AI 润色）才是根治。
6. **本诊断的边界**：基于代码+截图静态证据；"导出不能用/骨架卡死"未在真机微信复现（冒烟须 ssh+真实账号，禁本机 curl 打 8001——Mimosa SSRF 拦截）。P0 修完必须按验收路径真机回归。
7. **最重的一条**：COMPANY_REVIEWS 假评价是红线问题不是 UX 问题。劝退卡教训：说假话错一次十倍代价。应视作 P0。

## 判读（按 09-14 已拍板的"面板口径"重读）

1. **"提醒扩到 4 类"分支死**。原判据（+10pp → 扩 4 类）的两种结局里，实测连起点都没有；且 09-14 拍板已把推送移出产品方向（公考雷达免费+官方短信已覆盖纯提醒，本产品价值在数据之外），该分支本来也已关闭。
2. **回传面 zero 是真问题，但根因不在提醒**。北极星（条件完成率+回传率）的回传面 0/0：没有订阅、没有回传行。缺口漏斗（005 面板）的冷启动两问起步正是为此设计的获取路径——数据支持"两段先行、增量段显式空态"的 005 规格，不需要改。
3. **90 天冲刺/学习计划/连击/微行动栈进入折叠候选**。瘦身收尾与验收计划 9/18 行预留的"折叠动作"决策，现在有数据了：全期 0 次任务完成、窗口期 0 活跃。按砍刀标准（竞品都有→不做、要简单实用）与"无数据不假装"，推荐折叠而非继续维护为增长面；栈内 pipeline（reminder/streak/micro_action service + D2 开关）是否随折叠批量下线，属独立瘦身批次，走 008 同款"先审计再删"流程，不挟私报复。

## AAR 三问

- **问题对吗？** 对了一半。实验设计测"中断次日拉回"，但前提（有人每天在完成任务）从未成立——上线前该先验证输入面有流量，再开观察窗。这是"度量前置校验"缺口。
- **带隐患了吗？** 带了：观察窗开着让人以为实验在进行，实际空转 13 天无人察觉——**静默空转与静默失败同样危险**（对账家族第四课：不但要"测试有牙"，还要"实验有心跳"）。
- **踩已知坑了吗？** 踩了一条新形态的旧坑：**幂等分支静默返回 = 状态不可观测**（`get_job()` 命中即 return 不打日志），差点让我把"日志缺席"误判成"job 没注册"——对账家族第四课的又一实例：不但要"测试有牙、实验有心跳"，**幂等路径也要留一行"已存在，跳过"**，否则下一次排查的人只能猜。顺手改法（一行 log）留给执行会话，不阻塞方向判断。

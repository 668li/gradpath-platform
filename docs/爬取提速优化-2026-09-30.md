## 5. 节流 vs 并发：直接冲突的解法

**冲突**：我建议"跨域并发 4→16 提速"，合规建议"per-domain 5-10 秒（现 1.0 秒）"。

**解法**（合规优先，提速让位）：
- per-domain 间隔 **1.0s → 2.5s**。⚠️ **此值是工程取值不是合规结论**（审查判定原方案此处属拍脑袋且不可审计）：外部"5-10s"未标注出处；且**合规价值取决于 peak request rate（并发×频率×时长）的综合效果，而非单请求间隔**。
- **峰值重算（v3.1 修正原方案的算术错误）**：原方案"2.5s + 跨域并发 8"的瞬时峰值**可能高于**原配置"1.0s + 并发 4"——因为跨域桶多时同一 host 仍可能被并发命中。正确做法是**以 peak request rate 不高于原配置为约束**反推并发档位，实测校准后再定，不预设数字。
- **40-70 秒墙钟标注为待验证估算**（审查指出）：本地实测 1.0s 下同域深抓 0.70 页/秒，瓶颈可能在节流、也可能解析/落盘占用大头；单纯调节流参数的边际收益可能远低于预期。**必须实测验证，不得写进验收指标。**
- WAF 硬拦 3 校（北邮 412 / 南航 488 / 安大 412）标记为"站点不欢迎"，**不换 UA、不换 IP 撞**（外部明确：这是"强行突破反爬技术措施"，法院认定不正当性的核心情节）。**WAF 策略会随时间变化，需定期重探**（审查补充），排除清单不是一次性的。
- **附件校验三件套（v3.1 补定义，审查指出原方案只写"校验"是空话）**：①**Content-Type 校验**（PDF 须 `application/pdf`）；②**magic bytes 校验**（`%PDF-` / xlsx `PK` / doc `D0CF11E0`）；③**Referer/Origin 请求头自动补全策略**（带正确 Referer 属正常浏览器行为，不算绕过防护）。三者缺一即拒收该附件并记 not_found。
- **DNS 枚举改被动（v3.1 采纳审查）**：主动子域爆破在部分站点策略下可能被论证为"试探性入侵"，风险高于访问公开静态页。**改用 passive DNS 与证书透明度日志（CT logs）** 解析高校子域，去掉主动枚举。
- **freecho/yzw 法律边界收紧（v3.1 采纳审查）**：**"仅内部使用"不是安全港**——若产品最终向用户提供的是"经该数据校验过的结果"，因果关系仍然存在。使用时须：仅比对不复制、不入库不对外展示、保留 MIT 版权声明、记录每次使用的时间与范围以备举证。
- 32 校中浙大/兰理工/扬大是 curl 000（网络不可达非 HTTP 错）→ 换出口复测再判死，不直接记死。

## 一、审查意见逐条处理

### a) 研招网红线改口径 —— **原论证不成立，已撤回一刀切建议**
**审查意见**：把"合规"降维成"技术手段合规"，遗漏三层——①robots 404 ≠ 授权（2025 修订《反不正当竞争法》商业数据专条；链家诉神鹰案"公开数据不意味着可不受限制地获取和使用"）；②不绕验证码 ≠ 安全（淘某诉慢某案认定要素是"绕开风控机制、突破正常访问权限、大量爬取妨碍平台正常运行"）；③**商业用途定性缺失**——内部辅助 vs 产品内展示 vs 对外 API 风险等级完全不同。
**处理**：**撤回**"技术可达即放行"的一刀切建议，改为**先用途定性 → 再定红线口径 → 最后谈技术放行**的三步顺序，并新增待你回答的问题：自划线数据在产品里的呈现形式。若对外展示，须先做聚合化/去标识化设计。

### b) AGPL —— **审查结论与 v3.0 均不采纳，第三种定性成立**
**审查意见**：判"持续暴露状态"，称 AGPL 义务触发点是"通过网络提供服务"而非"修改后分发"，SaaS 场景可能已触发。
**我方独立验证**：`/api/pipeline/ingest/file` 端点鉴权为 `Depends(get_admin_user)`（admin-only）；fitz 生产调用点仅 2 处（该 admin 端点的上游 + 内部入库脚本）。
**处理**：定性为**边界态**——技术要件当前不成立（非普通用户可远程交互），但**任何把 PDF 解析开放给非 admin 用户的改动即时触发**。新增**立即生效的代码级门禁**（禁止 fitz 挂非 admin 端点，加静态守卫），法务/采购决策（买 Artifex 授权 vs 移除 fitz）仍待你裁决。**未盲从审查，也未坚持原判断。**

### c) 三路对拍 —— **降级为"扩样本后决策"，不因 6 样本换主力**
**审查意见**：6 个 PDF 统计上不成立；外部 32% 的测试集构成不明；"与往年对比"作自动拒绝会产生假阳性；人工队列无 SLA 规划。
**处理**：①取消"换主力"决策，先扩到 **30-50 个真实 PDF 语料**再定；②"与往年对比"降为 warning 只标记不拒绝，"量纲校验"保留硬拒绝；③人工队列 SLA 与容量列为待规划项。

### d) 节流 2.5s —— **承认为工程取值，并修正一处算术错误**
**审查意见**：2.5s 属拍脑袋且无出处；合规价值取决于 peak request rate 而非单请求间隔；墙钟估算需验证。
**处理**：①标注为工程取值非合规结论；②**修正原方案算术错误**——"2.5s + 并发 8"的瞬时峰值可能高于原"1.0s + 并发 4"，改为**以 peak request rate 不高于原配置为约束**反推并发档位；③40-70 秒墙钟标注为待验证估算，不进验收指标。

### e) 遗漏风险 —— **补三项 + 依赖分叉**
| 遗漏 | 处理 |
|---|---|
| "附件校验"是空话，没定义校验什么 | 补三件套：Content-Type + magic bytes（`%PDF-`/`PK\x03\x04`/`D0CF11E0`）+ Referer 自动补全策略，缺一即拒收记 not_found |
| "仅内部使用"不是安全港 | freecho/yzw 边界收紧：仅比对不复制、不入库不对外展示、保留 MIT 声明、记录使用时间范围备举证 |
| DNS 主动枚举的合规性未讨论 | **改用 passive DNS + 证书透明度日志（CT logs）**，去掉主动子域爆破 |
| WAF 排除清单是一次性的 | 补：WAF 策略会变，需定期重探 |
| P0 与 P1 依赖分叉未说明 | 补：P1 首选源"研招网院校库"依赖 P0 红线裁决；若维持红线则 P1 整体换源，两分支二选一不可并行 |

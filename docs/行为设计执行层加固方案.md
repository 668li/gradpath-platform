| 原方案声称 | 实证结果 | 影响 |
|---|---|---|

## 0. 一句话定位

**用户在本平台要完成的「行动」，不是线上的点击，而是把「来决定报名哪条路」这件事，拆成一个个低成本、可验证的小行动，并在一个高风险的申报/考试节点前保持不中断。** 现在的产品把所有执行表面（微行动/行动打卡/计划/冲刺/连胜/复盘）都建好了，但**缺少把它们推起来的「提示/触达层」，而且有两个行为学完整性漏洞会把任何实验数据污染掉。**

先用第一性原理把「基本事实」和「习惯性假设」分开——分不干净，下面全是换说法重抄原方案。

## 1. 第一性原理拆解（kazike 07）

### 1.1 已经确认、无法绕开的基本事实

| # | 事实 | 含义 |
|---|---|---|
| F1 | 产品护城河 = `POST /api/assessment/interpret`（测评类型 × 真实报考数据 → 个性化路径卡），**零 LLM、纯数据**。 | 行为层必须服务于「让用户更愿意去做」而不是替代数据真相，更不能为了设计出数据造假。 |
| F2 | 「行动」是决策 → 小行动验证 → 承诺 → 关键节点，不是一次点击。 | 行为设计的对象是「断点之间的连续性」，不是单点按钮转化率。 |
| F3 | 现有执行层已经非常完整：微行动(7天)、行动今日清单、连胜(主/微双轨)、职业规划、学习计划、人生设计90天冲刺、复盘(阶段/周)、成就/XP/徽章、成长模式。 | 不是"从零建"，是"把这些串起来 + 补缺失的提示层 + 修漏洞"。 |
| F4 | ~~缺的是一层：零定时器、零推送生产端~~ **【2026-09-04 对抗式复核修正】** 定时器其实存在：APScheduler + Redis JobStore 已在生产跑爬虫调度（`crawlers.py:_build_scheduler_jobstore`，main.py startup `seed_default_schedules`，A9 已修多 worker 重复执行）——所以加一个"行为提醒 job"是现成模式不是新基建。真正缺的只有：①通知生产端（notification 表零行为类生产者）②**前端 WebSocket 客户端**（全前端 grep `new WebSocket` 零命中；唯一"实时"是 nav 角标每次挂载拉一次 unread-count，nav.tsx:210-222，无轮询）③站外通道（SMTP 是 auth_service.py:88 的 TODO；PWA push 被 待备案/HTTP 裸 IP 卡死）。 | 提醒层的真实可达面 = **已经在站内的用户**。杠杆从"调度推送召回流失者"修正为：修好站内提示（调度 job→create_notification→现有角标/列表展示）+ 站内钩子显眼化；站外触达是 HTTPS/备案 解锁后的独立轨道。 |
| F5 | 信任经济学是第二护城河——劝退/敢说真话、劝退卡、互惠回传。 | 行为手段若被知觉为「操纵/暗黑/催缴」，会反噬信任本金。**行为设计 ≠ 操控；EAST 里那个 Easy/Social/Timely 可以适度，但不能假数据、不能制造虚假紧迫。** |
| F6 | 两条硬约束：真实数据零造假；覆盖考研/考公/泛就业/在校等非程序员身份。 | 每条机制都要问「一个二本学护理、要考公的女生用得上吗」，不能只服务技术人群。 |

### 1.2 习惯性接受、却没验证过的假设（= 原方案里「只修表面」的部分）

| # | 假设 | 为什么可疑 |
|---|---|---|
| A1 | 「加更多积分/徽章/连胜就能驱动用户」 | 产品已有 XP/7级/15徽章/双轨连胜，但**全是惰性发放**：徽章只在 GET /profile 时才 `check_and_award_badges`；看板把「打开」记成活跃（`dashboard_service.get_overview()` 每次打开都 `record_activity`）。继续加奖励 = 在噪声数据上加更多装饰。 |
| A2 | 「用户会自己回来」 | 已被反证：所有提醒都是被动。微行动 D2 不回来计划就搁浅；90天冲刺无哨兵；复盘节律靠自觉。 |
| A3 | 「行为设计 = 游戏化」 | 混淆。游戏化（积分/徽章/排行）只是 Fogg 里「Motivation」的一小块，而且是边际递减最厉害的一块。行为设计的主力是**能力(简单化) + 提示(时机) + 即时满足**，不是加数值。 |
| A4 | 「提醒会打扰用户」 | 被高估。对**刚决定要做、卡在入口/忘了回来**的用户，一条 Timely 的 Facilitator 提示不是打扰而是帮助。真正的打扰 = 与用户当前意图无关的无关推送。 |
| A5 | 「两套连胜并行没问题」 | 有问题：`actions` 页的 ActionStreak 与看板的 StreakRecord 是**两套压缩并行的账本**，用户在不同入口打卡会得到两本记录、互相稀释感知价值。 |
| A6 | 「微行动必须让用户写下发现才叫完成」 | 反 Fogg 的 Ability 原则。`micro_action_service.complete_task` 强制 `user_response` 非空——用户做了行动但不想打字就永远无法完成任务 = 把「简单」做成了「难」。

### 1.3 真正想实现的目标

把用户从「知道了但没动」推到「动了一次」，再用「连续性」维持到关键节点，全程**不造假、不操纵、对得起信任**。KPI 不是「打开数/时长」（虚荣指标，且现在连打开都被错误记成成就），而是：
- **有意义的行动完成数**（微任务完成 × A + 行动打卡 × B + 冲刺周复盘 × C），且**只算真实行动，不算打开**。
- **行动连续性 / 回回率**（D2 后还回来、两套账本合一后的真实连胜）。
- **关键节点命中**：进面线发布日前做了该做的准备动作。

北极星沿用记忆里定的「条件完成率 + 回传率」，本方案只支撑它，不另立指标。

### 1.4 现实中的资源与约束

- 全栈 FastAPI(8001) + Postgres + Next.js，Alembic 单头，生产走 bundle 部署（`update_from_bundle.sh`）。**改表/加迁移 = 走完备的迁移+冒烟纪律**。
- 有一条可用的基础设施：`notification` 表 + WebSocket 推送通道现成，但零生产端。加「调度器」即可盘活。
- 无 celery periodic 生产使用（可以加，也可以用现有 `schedule`/哨兵）；Mimosa 安全闸会拦网络脚本/动态 DDL。
- 用户当前在并线推进：life-design 独立交互页（Plan A 待拍板）、花式测评改造。**本方案不与这两条冲突，且第一条建议就是修基线漏洞 + 补提示层，属于任何方向都要的「打底」。**

## 2. 把「书里的内容」拆成可复用的操作原语

理论 → 产品动作。每条原语给：源头、一句话机制、在 GradPath 的具体 UI/后端形态。

### 2.1 Fogg 行为模型 B=MAP

- **理念**：行为发生 = 动机 × 能力 × 提示同时到位。行为没发生的唯一原因是三者缺一。**当能力足够时，一个可用的提示就能触发行为；当能力不够时，给再大动机也没用。**
- **可复用操作原语**
  - **OP-能力链（Ability）**：复杂行为的可行性取决于「最弱一环」。给每个行动标注成本六维（时间/精力/脑力/社交成本/非常规/金钱），把最弱一环降到「几乎不用想」。Fogg 名言 *simplicity is a function of your scarcest resource at that moment*。
    - 形态：微任务的「2分钟版」；回复盘表单的「一句话版」；写不出来的「语音转文字兜底」。
  - **OP-提示三型（Prompt）**：Facilitator（降低难度的一键直达/预填）、Signal（用户已高动机时的普通 CTA）、Spark（低动机时给激励文案）。
    - 形态：**后端按「动机×能力」状态分流下发不同提示**。正在做的/高动机 → Signal；忘了回来 → Facilitator（一键回到上次停的步骤）；未决定 → Spark。
  - **OP-锚定（anchor → tiny → celebration）**：把新行动挂在用户已在做的动作后面（habit stacking）。Headspace 实例：*"I will count breaths as soon as I get out of the shower."*
    - 形态：复盘/打卡提供模板锚点「起床后/到工位后/睡前」；完成后给即时小庆祝（对勾+XP+一条鼓励）。

### 2.2 Atomic Habits 四定律（James Clear）

- **理念**：习惯环 cue→craving→response→reward。好习惯 make it **obvious / attractive / easy / satisfying**；坏习惯反四则 **invisible / unattractive / difficult / unsatisfying**。
- **操作原语**
  - **OP-显眼（obvious）**：行为入口固定+置顶+角标；无信号时自动补一个 cue。
  - **OP-诱人（attractive）**：把低频高价值动作与已有高频动作绑定展示（habit stacking 列表）。
  - **OP-容易（easy）**：默认给「2分钟版/入门版」最小任务，而不是完整任务入口（2-minute rule 网关习惯）。
  - **OP-即时满足（satisfying）**：完成瞬间对勾动画+XP+连胜+1，写在动作事务内（不是 profile 懒发放）。**这直接对上 2.1 的 celebration。**
  - **OP-never-miss-twice**：断一天没事，别断第二天。→ 后端容错：第1天漏做仅轻提示，第2天才触发挽救提醒 + 给1次冻结（与 Loop forgiveness 同源）。
  - **OP-习惯叠加**：`After/Before [当前习惯], I will [新习惯]`。

### 2.3 Hook 模型（Nir Eyal）

- **理念**：Trigger → Action → **Variable Reward** → Investment。外部触发=推送，内部触发=用户脑内的念头。
- **操作原语**
  - **OP-可变奖励**：结果随机池（连胜彩蛋/随机徽章/「你的同分人群里 3 个去了 X」——后一条是真数据、随机抽，既新鲜又不造假）。
  - **OP-投资沉没化**：让用户留下自己的输入（自定义 if-then、自定义标签），提高离开成本，但这必须是**真价值**，不是强制锁。

### 2.4 EAST（英国 BIT）+ 实施意向（Gollwitzer）

- **EAST**：Easy / Attractive / Social / **Timely**。
- **实施意向**：任务创建强制填 `如果[情境]，那么我做[行为]`，把意图编码成可触发。
  - **OP-情境触发器**：把 if-then 存库并映射成提醒触发条件（如「每天 21:00 → 填一条职业复盘」）。

### 2.5 发散 ↔ 收敛（用户点名的「扩大发散」）

来自 life-design / Odyssey 的 4 阶段（审计 → 发散多地 → 原型 → 选择）。**执行层的正确顺序是：先发散（让用户多看清几条路/几个做法）——再收敛（定一条、拆小行动）——再执行（提示层接棒）。**
- **操作原语**：
  - **OP-发散闸口**：用户在 decision/评估结果页给「还想看别的」出口，扩展至少 3 个并行可能方案（3 个 Odyssey plan：继续现路 / 转路 / 最小风险路），用真实数据给每条打分，**不催促立即选定**。
  - **OP-收敛闸口**：用户选定一条后才进入「拆 7 天微行动」；微行动本身 D1-D3 也是发散验证（调研/访谈两种都看），D4-D7 收敛（实践+复盘）。**现在微行动已经悄悄做对了发散→收敛，但缺进出闸口的引导文案。**

## 3. 映射：十大执行表面 × 该补的原语

（当前现状出自本会话对 `frontend/app/(app)/*` 与 `backend/app/services/*` 的实测盘点）

| 表面 | 用户要做什么 | 现有机制 | **缺的原语 / 要修的洞** |

| **微行动(7天)** | 每日1个15-30min任务(调研/访谈/实践/复盘) | 7日承诺、进度、AI洞察、D7报告 | ⚠**修 `complete_task` 强制打字**；缺「D2未回来召回提醒」；加如果-那么锚点；D1-D3发散/D4-D7收敛引导 |

| **学习计划** | AI生成计划、套模板 | 进度、模板墙 | 修编辑残桩 + subjects 没渲染；给划目标的2分钟版最小任务 |
| **人生设计90天冲刺** | 审计→愿景→冲刺→周复盘→季回顾 | 强漏斗、90天倒计时、衡量目标、周复盘+AI教练 | ⚠**审计答案仅存内存、刷新即丢**；补「周复盘到期提醒+冲刺到期哨兵」；发散/收敛闸口文案补上 |
| **复盘(阶段/周)** | 沉淀经验 | 模板、AI成稿、4层周报视图、来源徽标 | 补「周末哨兵提醒」；周报数据不足硬拒→给「2分钟一句话版」兜底 |
| **成就/XP/徽章** | 看等级玩徽章 | 7级XP、15徽章、公开技能页 | ⚠**徽章从 profile 懒发放改为完成动作事务内即时发放+toast**；给「下一个徽章还差什么」的行动提示(别让页面是死的) |
| **成长模式** | AI分析行为模式 | 校准仪表、模式卡、建议 | 补「每月回来」的定时哨兵兑现文案 |
| **通知收件箱** | 查看通知 | 只读，无生产端 | ⚠**写调度器 + 让行动/规划/连胜/复盘成为 notification 生产者**（这是全方案的最大单点） |

**合成结论**：这 10 条缺的东西高度收敛——80% 落在**「一个调度器 + 提示生产端 + 三处完整性修复」+ 少量「减少打字难度的兜底」+「发散/收敛闸口引导文案」**上。**不是 20 个独立新功能，是 4 个横向能力。**

## 4. 对抗式审查（kazike 06 专家会诊视角互相质疑）

三个真正互补的视角 × 它们各自承认的风险：

### 视角甲：行为设计/产品增长
- 回答：最大杠杆在提示层 + 即时反馈 + 修 baseline。少做花哨，多做「用户决定后 48 小时内的那一次召回」。
- 最容易忽略的风险：**提醒做过头 = 变成 Beeminder 式催债 App 的反感**；两套账本合并会动线上逻辑、需防回归。

### 视角乙：信任与数据纪律
- 回答：任何提示文案都不能编造紧迫感（如「仅剩 3 个名额」这类假稀缺 X）；免责/劝退卡优先于诱导；变奖励池只能用真数据随机抽。
- 最容易忽略的风险：**行为层会悄悄把「完成任务」写成「打开就算完成任务」，这正是 `dashboard_service` 现在干的事——那等于在造假成就数据**。必须先在源头堵死。
- 视角丙：工程现实
- 回答：调度器是几百行规模，但迁移+冒烟+部署成本高。**提示层可用现有通知表+WebSocket 盘活，不必上 Celery。**
- 最容易忽略的风险：联合并两套连胜、改打完成判定，都是**动的行为核心逻辑**，逻辑没想清就上会在生产留 bug。

### 三方互相质疑后
- **共同认可事实**：必须先修完整性问题，否则任何新机制都在污染数据上叠加。
- **真正分歧**：「提醒强度」——甲要强 Timely，乙怕打扰伤信任。
- **背后假设**：甲假设「多数用户忘了回」，乙假设「多数用户能被召回」。→ 这是**事实题，应该用实验测**，不是继续争。

### 综合结论
1. **最推荐方案**：先修基线（2 处完整性 + 强制打字），再补「最小调度器 + 提示生产端」只覆盖 4 种高价值提醒（行动逾期 / 断签前警告 / 微行动 D2 召回 / 周复盘哨兵），最后做发散/收敛闸口文案。
2. **适用条件**：这些改动不动数据真相、不改信任边界，对所有身份人群无害。
3. **最大风险**：调度器 + 合并连胜动核心逻辑 → 需强冒烟（现有 141+ 测试风格）。
4. **退出条件**：如果修完整性问题后，行动完成数依旧低（说明不是「忘了提醒」而是「行动本身没用/门槛太高」），则停止加提醒，回到「降低任务真实成本」（访谈/真题门槛的合理性），而不是继续堆推送。
5. **第一步行动**：见 §5。

## 5. 最小实验（kazike 10）——【2026-09-04 重设计】站内版

原设计"D2 晚 21 点推送召回"经复核**不可行**：SMTP 是 TODO、PWA push 被 HTTP/备案卡死——**提醒只能到达已在站内的人，召回不了没回来的人**。重设计为站内两段实验，仍然低成本、可逆、一周内可判：

- **要验证的假设**：①用户"回来但看不见/忘了计划"是行动断链的主因（原假设①的可测子集）②降低打字门槛提升完成率。
- **实验 A（站内 Facilitator 续做卡）**：微行动 D1 完成但 D2 未做时，dashboard 顶部渲染续做卡「上次停在第 N 天任务：XXX，点击继续」（深链 `/micro-actions`），同时 `push_notification` 写一条 reminder 通知（type=reminder、link 现成）。开关 `MICRO_ACTION_REMINDER_D2` 控制，hash 分流。
- **实验 B（顺手带上）**：`complete_task` 放开 min_length=1 → 可选 +「先完成，稍后补记录」；对比放开前后任务完成率。
- **投入**：A ≈ 1 个调度 job（复制 `seed_default_schedules` 模式）+ 1 个通知生产端 + 1 个看板卡片 + 角标 60s 轮询；B ≈ schema/service 各 1 行 + 前端按钮。合计约 1-2 个工程师日。
- **观察指标**：分流组 D1→D2 续做率、续做卡点击率、通知→点击→完成漏斗。**注意口径：这测的是"站内提示对已回来用户的拉动"，测不了召回流失用户**——后者没有通道，不装假。
- **支持继续**：续做率 +≥10 个点 → 提示层扩到 4 类提醒。**提醒停止**：无提升 → 回 §4 退出条件，转降任务真实成本，而不是堆推送。
- **真召回（P3 独立轨道）**：等 HTTPS/域名备案解锁 → PWA push（Service Worker，数据结构已齐）或接邮件服务商。备案前不做。

## 6. 落地分轨 & 优先级（给后续动手用的清单）

### P0 先把实验数据弄干净（天级）
1. ⚠修 `dashboard_service.get_overview()` 不再把「看板打开」记成活跃 —— `record_activity(..., "dashboard")` 不应续签 streak。
2. ⚠微行动 `complete_task` 允许空/极短 user_response，或提供「先标记完成，稍后补发现」（语音转文字兜底）。
3. ⚠合并两套连胜账本（ActionStreak ↔ StreakRecord 二选一，业务上保留看板那套 Duolingo 设计）。

### P1 最小提示层（周级，实验上量前不全面铺）【09-04 按复核修正】
4. 调度 job：**复制现成 APScheduler 模式**（`crawlers.py` seed_default_schedules / add_job，RedisJobStore 多 worker 共享），注册行为提醒类任务（§5 实验 A 的 D2 续做提醒起步）→ 扩到「行动逾期 / 断签前警告 / 周复盘哨兵 / 90天冲刺到期」4 类。
5. 通知生产端：`push_notification()` 一行即写库+推 WS（`NotificationType.reminder` 枚举现成、`link` 深链字段现成、零迁移）；**前端补最后一米**：nav 角标 60s 轮询 unread-count（10 行），WS 客户端可缓——轮询已够实验用。

### P2 传播与闸口（双周，非阻塞）
6. 徽章改为完成动作事务内即时发放 + toast + 「下一个徽章还差 X 步」。
7. 行动/复盘加「2分钟一句话版」兜底；计划创建给一键从模板最小版。
8. life-design 审计答案落库；发散(3 Odyssey)/收敛(拆微行动)闸口文案。

### 红线（不越）
- 不造假的紧迫/稀缺文案；变奖励池只用真数据随机抽；不把打开伪装成完成；每身份人群过筛（非程序员/在职非技术）。

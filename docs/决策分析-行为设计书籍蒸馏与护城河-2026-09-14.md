# 决策分析：认知觉醒/福格行为设计蒸馏 skill 与护城河（2026-09-14）

> 触发：用户提问"把《认知觉醒》《福格行为设计》用 cangjie-skill 蒸馏成 skill 集成到项目，可行吗？不清楚作用与集成位置，要求第一性原理 + 对抗审查"。
> 方法论：第一性原理推导 → 对抗式审查（红队）→ 修订结论与建议。本文件同时作为决策留档。

## 一、先定义清楚：这两个"东西"是什么

- **cangjie-skill**（实测读过）= 把一本书蒸馏成一组 **SKILL.md**（RIA-TV++ 流水线：整书理解→5 提取器→三重验证→RIA++ 构造→压力测试）。产出物是**文本型提示词包**，每个 skill 含 R/I/A1/A2/E/B 六段 + 测试 prompts。**它的形态是"给 AI agent 用的作业手册"，不是产品功能、不是算法、不是数据。**
- **SKILL.md 的定位**：控制 agent 在特定情境下的行为（何时触发、按什么步骤执行、何时不适用）。它影响的是"AI 怎么做事"这一层。

## 二、第一性原理推导

**L0 产品在卖什么**：用户买的是"不选错 + 不白干"（不选错=判断，不白干=执行），按 09-14 拍板的替代栈 = 判断层 × 可信资产 × 缺口漏斗。

**L1 护城河的判定标准 = 是否可被低成本复制**。逐层过：
- 书：《认知觉醒》《福格行为设计》公开出版物，**人人可买可读** → 不是护城河；
- 蒸馏出的 SKILL.md：文本，竞品可拆同一本书、甚至可逐字复制 → 不是护城河；
- 基于书设计的产品机制（微行动、即时反馈、提醒）：**机制全部公开**，公考雷达等随时可抄 → 不是护城河；
- **用户数据闭环**（条件账本缺口、时间线回传、复盘原则库、行为轨迹）：竞品拿不到，越用越厚 → **护城河在这里**。

**L2 集成路径的唯一可行形态**：产品不能直接"挂载 skill 文件"——但产品内的 **LLM 调用（prompt）与规则引擎**本质就是"内置的 skill"。所以"集成"= 把书的原则**翻译成产品机制与 prompt 纪律**（改行为），不是新增可见页面。

**L3 已有资产盘点（实测）**——书里的机制大部分已经在跑：
| 书中原型 | 项目里的对应物（已存在） |
|---|---|
| 福格 B=MAP（行为=动机×能力×提示）| 行为设计实验 P0/P1（时区修复+开关已上产）、003 三件套（行动钩子=提示、记忆感=动机、深链=降低能力门槛）|
| 福格微行为/庆祝 | 微行动卡（`micro-action-card`）、行动钩子实验 |
| 福格"降低摩擦" | 冷启动两问起步（L4）、缺口面板 pull 形态 |
| 认知觉醒·元认知 | 006 复盘方法论（双我思维=元认知工具化，已出规格）|
| 认知觉醒·舒适区边缘 | `recommender.py`/`life_wheel_service.py` 已有痕迹；考试路径本身的难度梯度 |

**结论：缺的不是"两本书"，是 2–3 个具体机制**（差异化地看，而非齐平地补）。按"缺什么补什么"蒸馏，可能连一本书都不必整拆。

## 三、对抗式审查（红队逐条给判）

【P0·击毙】**"蒸馏 skill = 护城河"**。证据：书公开可买；SKILL.md 是文本可复制；机制公开可抄。三方同向。真实护城河=机制接上用户数据闭环（回传率/原则库/缺口账本），竞品抄机制也抄不走积累。
【P0·击毙】**"把 skill 文件塞进产品当功能"**。产品无"skill 挂载"面；正确做法=原则→机制/prompt 纪律（改行为，不加页面）。
【P1·降级】**认知觉醒整本蒸馏**。该书主体是个人成长/心智系统叙述，非可执行决策框架；强拆易产出心灵鸡汤（撞 cangjie 三重验证 V3"不是常识吗"）。**建议：不蒸馏**——其可执行部分（元认知、边缘学习）项目已有关联实现。
【P1·降级】**福格整本蒸馏**。可执行性高（B=MAP/行为六要素/庆祝/微行为），但产品已在跑核心机制，边际收益递减。**建议：只提炼"尚未系统化"的 2 个机制，不必整拆**。
【P1·修正】**"蒸馏来管我方工作流"的定位**。若蒸馏产物只用于本席位写规格/审查（内部工具），其价值与产品护城河无关，不应记入产品资产；成本（整书阅读+流水线+验证）需与"低频但高杠杆"的实际使用频次对账。
【P2·风险台账】**加机制 = 加负担**。福格第一性=把行为变简单；产品端加任何"认知"元素必须先过"减少用户操作量"的筛，否则违反该书的根原则。
【P2·真实瓶颈提示】**回传率是护城河地基，但它是行为问题**：用户愿不愿认真填账本/复盘决定数据资产厚度。这才是行为设计真正该赋能的地方（006/005 落地时用机制提升回传质量），但现在不缺"又一套机制"，缺**把已上产机制用到位**。

## 四、修订结论

1. **不把"蒸馏 skill"当护城河，也不直接集成 skill 文件**；护城河=数据闭环（原则库/账本/回传）+ 把书的原则翻译成机制与纪律。
2. **认知觉醒：建议不蒸馏**（避免鸡汤化，且已有对应实现）。
3. **福格行为设计：建议只提炼 2 个机制的落地清单**（不必整本拆）：
   - **庆祝/即时微反馈**：完成节点/补缺口/提炼原则时给即时正向反馈（成本最低、效果最强；可挂 005 面板条目与 006 原则卡）；
   - **触发-能力-动机简化检查**：行动项按福格式改写（"当 X 时，做 Y"，且摩擦降到一步）。
   （另有一个候选："行为设计六要素 checklist 进规格审查"——按 P1 修正，属内部工具范畴，单独决策。）
4. **护城河正解复盘**：机制可抄，**接上数据闭环后的机制抄不走**；原则库（006 已接对话注入）就是这个闭环的第一个实例，验证它比再拆两本书更值钱。

## 五、建议的下一步（等你拍板）

- **A 不立案**（推荐）：本分析归档即可；006/005 落地时把秋季两个机制直接内联进实现（庆祝反馈、福格式触发文案），不单独立项。
- **B 立案（轻量）**：把上述"2 机制落地清单"写成 007-behavior-design 小 spec（不拆书、不新增页面；挂 005/006 实施批次），排期与 005/006 同窗口。
- **C 立案（重）**：整本蒸馏福格（+可选认知觉醒）→ 产出 SKILL.md 包 → 内部工作流使用。**不推荐**：成本高、与产品护城河无直接因果，且易变成"收藏夹式学习"。
- **D 备档**：若未来要做公开的"学习科学内容层"（面向用户输出方法论内容），蒸馏才有产品级意义——但那是内容产品，与当前伴随层战略不同线，需另立第一性论证。

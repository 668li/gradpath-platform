## B. P0 修复清单（仅代码级可修、不依赖 AI）

1. **路径冲突调解卡永久不可见（方法用错，最严重）**
   - `frontend/components/decision-copilot/path-conflict-card.tsx:471` — `useApi()` 发 GET `/api/path-conflict/detect`，但后端 `backend/app/api/path_conflict.py:29` 只注册了 POST /detect，GET 被 `/{resolution_id}` 路由吃掉返回 422，组件 `if (error) return null` 静默隐藏。
   - 修法：改用已有的 `pathConflictApi.detect()`（lib/api/decision-copilot.ts:159，POST）+ useEffect 触发 + mutate；或后端给 /detect 加 GET 版本。注意生产库已有一条探针触发的 pending conflict 记录（decision_review_queue），修复后真用户即可看到调解卡。

2. **预验尸分析无 LLM 兜底，裸 500**
   - `backend/app/services/decision_analysis_service.py:116`（analyze_premortem）——LLM 挂时直接 500 INTERNAL_ERROR；同文件 `generate_red_team_questions`（:182）已有"零 LLM 可跑"规则兜底，premortem 应同样加模板聚类兜底（按原因关键词聚类+固定保障措施），或最低限度转 503 AI_UNAVAILABLE 让前端提示一致。

3. **`/{id}/ai-analysis` 错误契约不统一**
   - `backend/app/api/decision_analysis.py:96-111` 只捕 ValueError→404，AI 异常裸 500；应与 `ai.py` 的 AI_INTERNAL / decision-os external-verify 的 503 AI_UNAVAILABLE 语义对齐（前端 saveThenAnalyze 已能容忍，但决策实验室详情页"重新生成"会看到裸 500）。

4. **模拟器退役不彻底：2 处残留死链**
   - `frontend/app/(app)/failure-cases/[id]/page.tsx:233`、`frontend/app/(app)/family-dialogue/page.tsx:584` 仍 `href="/career-simulator"`，用户点进"已下线"页。按 09-26 拍板"入口已全部摘除"，应删链或改指向 /decision-engine。

5. **growth-patterns 页面是孤儿路由**
   - `frontend/app/(app)/growth-patterns/page.tsx` 无任何导航/页内链接指向它（nav.tsx 成长组只有 archive/retrospectives/achievements）。补进 nav 成长组 children，或在 growth/archive 页加跳转卡（数据接口本身可用）。

6. **（挂账级小修）退役后端仍暴露无鉴权 simulate**
   - `backend/app/api/career_simulator.py:73` /simulate 无 `get_current_user`，匿名可调；既然前端已退役，建议后端同批下线或加 410 语义（与前端拍板对齐）。

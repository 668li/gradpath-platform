## 一、第一性原理：AI 对话在本产品里到底为什么存在

1. 产品根本 job = 报考决策器（考研/考公/就业）+ 考公尖刀，北极星 = 条件完成率 + 回传率。信息流只是触发器（既定裁决）。
2. 用户在 chat 里的根本需求不是"聊天"，是**信息差翻译**：把独家真实数据翻译成针对"我"的处境的判断（"我这样的能报哪/差多少/值不值"）。
3. 所以 skill 的护城河判定标准只有一条：**这个 skill 的回答 vs 用户直接问 ChatGPT，差异是否来自 GradPath 独家数据**。差异不成立的 skill = commodity = 乱弄。
4. 调研确认的空位（这是战略判断的底）：
   - 国内考研侧**没有**"带本地数据库的对话式择校"开源实现（xuefeng-agent 是高考侧且 AGPL v3 不可抄代码；kaoyan-navigator 只是联网调研 skill，无库）；
   - 国际侧 career counselor 全是教程/玩具级，没有产品级开源；
   - 头部竞品（夸克/百度/知乎直答）全是"对话 + 结构化产物 + 数据库底座"三件套，没有一家纯聊天——且大厂不自建招录数据（字节/知乎直接接掌上高考），**我们的真实数据底座本身就是稀缺品**。

## 三、实现方案（按调研收敛为"三段式查库注入"，明确不做什么）

### 3.1 核心模式：代码过滤 top-N → 注入 → 来源标注（三段式）

调研最强结论（多源交叉验证）：小模型 + 无 function calling 基建约束下，唯一被验证稳的模式就是 xuefeng-agent 的三段式；**text2sql 明确禁用**（benchmark 86% vs 生产库 6-10%，且错误是静默的——返回错数据而非报错；dbt 2026：语义层/预定义查询 98.2% vs 概率性 text2sql 84-90%）。

```
第 1 段 参数归一化：LLM 把口语输入转 JSON 筛选参数（"一万三"→13000、省份、专业）
        —— JSON 输出 + _safe_parse_json 代码解析，替代 function calling，失败降级原文本
第 2 段 确定性查库：Python 执行预定义查询（条件账本过滤职位表 / 分数段查进面线），top-N ≤ 20 条
第 3 段 注入生成：结果带【数据库·来源URL·数据截止时间】标注注入 system prompt
        prompt 明文纪律："数据库没有就说没有，字段缺失留空，绝不编数"（抄 kaoyan-navigator 原则）
```

### 3.2 对话策略：槽位检查 + 显式澄清动作

- 数据型 skill 每轮先查必填槽位（择校=本科档/专业/目标层次；选岗=学历/专业/意向地区），缺则**输出选项化澄清问题（A/B/C/D/E）而非硬答**（来源：yanshen 问卷 skill + Google ACT"澄清 vs 回答二选一"）。
- 置信度按缺失字段数量分级 high/medium/low 并明示（来源：mcp-college-counselor）。
- 历史窗口控制防 answer bloat：重要画像信息走结构化存储（身份档案/条件账本已在库），不依赖对话历史。

### 3.3 输出规范（所有数据型 skill 统一）

结论前置（推荐 + 置信度）→ 风险审计清单（考研：爆热/缩招/推免挤压/复试线虚低/改考 408——抄 kaoyan-navigator 领域 know-how）→ 溯源附录（来源 URL + 数据截止时间）→ 免责一句话。年度配置（批次线/年份）外置 config 每年改一处。

### 3.4 skill 描述规范（抄 agentskills.io 官方标准）

description 必须写"做什么 + 何时用 + 触发关键词"（官方反例"Helps with PDFs."，正例含具体关键词）。主 prompt 精简，领域细节按需注入（渐进披露思想）。上线后用 `skill_used` 落库字段观测误触发/漏触发并迭代。

### 3.5 明确不做（对抗审查结论）

text2sql（静默错误重灾区）、LLM 自主 agent loop（30s 超时 + 100 配额）、流式改造（大工程）、通用陪聊/简历润色类 commodity、AGPL 代码抄袭（xuefeng-agent 只借鉴模式）。

## 五、站内数据搜索层（追加规划，2026-09-05 用户拍板"可以"后新增）

用户需求：AI 对话能调用站内数据搜索。调查结论：**已有两个半成品，缺的是中间那块**——
- `/api/ai/agent`（ai_agent.py:115 `_db_search`）已有"答案+sources+置信度"模式，但只扫 4 张内容表（经验帖/知识库/QA/黑知识），**护城河结构化数据（进面线/职位/薪资/院校情报）搜不到**；
- 前端 chat 气泡已预留完整展示位：`Message.agent_sources` + `agent_confidence`（types/index.ts:37-38，page.tsx:644-645 渲染"参考来源"标签+置信度条），**只差后端喂数据**。

### 5.1 架构：DataSearchService 三层

1. **白名单搜索器**（新服务 `app/services/data_search_service.py`，每个 = 一条确定性预定义查询，返回统一 `DataHit{title, content, source_table, source_id, url}`）：
   - `score_lines`：grad_scoreline_records（按校名/专业/年份；total_score_line>0 过滤脏数据，决策引擎同款纪律）
   - `positions`：gwy_position + gwy_province_position（关键词+学历+地区，top20）
   - `gwy_score_lines`：gwy_score_line（按部门/职位关键词）
   - `schools`：grad_school_intel（按校名/层次）
   - `market`：market_data + salary_benchmark（按行业/岗位关键词）
   - `content`：委托现有 RAGEngine（4 张内容表，含语义向量降级）
   - `peer`：同分去向（复用 build_peer_destinations）
2. **代码级意图路由**（`detect_data_intents`，零 LLM 调用）：关键词模式 → 选搜索器+抽参数（正则数字/枚举词表）。置信不足不查库——诚实降级。每轮上限 ≤2 个搜索器、注入总量 ≤1200 字。
3. **chat 链路接线**：`send_message` 中 skill 的 `inject_data` 与数据搜索合并注入【专有数据】；数据型 skill 通过 `data_domains` 类属性声明自己覆盖的数据域，chat 层去重防双注入；sources 持久化进 AI 消息 `context_snapshot.data_sources`，`SendMessageResponse` 增发 `agent_sources`+`agent_confidence`，前端预留 UI 直接点亮（send 响应拼字段+历史加载从 context_snapshot 恢复）。

### 5.2 纪律（全部来自调研实证）

- 绝不 text2sql（生产库准确率 6-10% 且错误静默）；搜索器全是白名单预定义查询。
- 零额外 LLM 调用：v1 路由纯代码，配额语义不变（1 轮=1 次调用）。
- 溯源标注统一：`[数据库·表名·URL·数据截至]`；查无数据明示"暂无数据"，prompt 明令禁编。
- 注入前过 `_sanitize_prompt_input` 同款清洗（搜索结果来自爬虫入库内容，防间接注入）。

### 5.3 与已拍板 skill 的交汇

择校对话师/选岗参谋的 `inject_data` 直接调 DataSearchService 对应搜索器——**一次基建，三处复用**（通用 chat + 两个数据型 skill），这就是"AI 调用站内数据"与 skill 批次的同一个工程。

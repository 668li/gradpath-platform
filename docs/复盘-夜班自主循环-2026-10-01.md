## ④ 根因拆解（5Why → 五类归属）

2. **bundle 相对路径 4 犯**：为什么口头纪律反复失效？→ 约束只在 prompt/记忆里，不在脚本里 → 子代理每轮新上下文，口头纪律无法遗传 → **工具能力限制**（本质是流程设计问题）。正解（未做，挂账）：把绝对路径校验写进 update_from_bundle.sh 第 0 行——机器闸优于口头纪律（对账家族「改系统优于改人」第三次验证）。
3. **修表象后才遇真根因（amend）**：为什么 CTA 修复没先挖根因？→ 修复轮 prompt 按「按钮没绑定」的验收归因直接派工，没强制先跑全站 30x 审计 → **方案设计问题**（先测量后设计纪律在子代理轮次内打折）。4d361c85 的 amend→converge 冲突就是这次偷懒的账单。
4. **磁盘闸**：外部资源约束，**时间资源问题**；流程应对正确（不绕闸、安全回收、挂账拍板）——这是系统按设计工作的样本，不算失败。
5. **密码明文落盘**：是我自己在子代理 prompt 里指示「凭据写 /tmp/night_probe_creds.txt」→ **prompt 缺陷**（指示即责任）。已清理；今后 prompt 要求凭据会话内传递用后即删。

## ⑦ AI 侧专属改进

- **子代理 prompt 模板**（本轮定型，直接复用）：背景已核实事实（防重查）→ 任务清单（带文件路径）→ 硬约束（外来 WIP/禁 reset/只 add 自己文件）→ 生产配方（隧道 18443/host-resolver-rules/converge 冲突配方/bundle 绝对路径加重音）→ 验收断言清单 → 回复格式（每项：文件/修法/验证+冒烟）。
